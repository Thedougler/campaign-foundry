# Scene pages

The common authoring procedure for `hook-scene`, `development-scene`, `cliffhanger-scene`, `climax-scene` and `resolution-scene`. Each skill supplies its kind's craft and card catalogue. This file defines their inputs, page contracts, conditional handoffs and completion. Read the kind's skill before designing.

## Steps

1. **Establish the assignment.** Follow `AGENTS.md` orientation and read `CONTEXT.md`, `docs/wiki-layout.md` and the current Scene template. Reuse a caller's completed orientation only when it covers this Campaign and request. Resolve the World, Campaign, Session, exact kind, destination path and completion owner. A `prep-session` child receives its Scene Chart row, Party, Opposition, Clues, Spotlight, predecessor alternatives and destination paths. For a direct DM request, retrieve the existing Prep and row. A bounded brief can supply the kind, premise, entry state, Threads, Spotlight and intended carry-forward. Add or update only that Scene's planning material, preserving the Session's objective. When no Prep exists, author the requested Scene from that bounded brief and link it from the Campaign overview rather than inventing an incomplete Prep. Missing Session intent goes to `plan-session`. Assembling or changing the whole chart belongs to `prep-session`. **Done when** the Scene's purpose and inputs are grounded and either a composing caller or this standalone operation is set to run the final gate and log.
2. **Ground the entry.** Use `qmd` to discover and retrieve relevant Wiki pages. For a Hook, retrieve the last played Recap and final Scene. Later Scenes need the predecessor's prepared outcomes. Every Scene also needs Party Sheets and goals, linked Threads, Locations, NPCs, Factions, Creatures, Items and applicable House Rules. Played events establish facts. Unplayed branches remain alternatives. Carry positions, knowledge, ownership, conditions, resources and any live clock that changes this Scene. Match each reused table-use fact to the actual owner passage: terrain costs, damage, checks, escape procedures and encounter state retain those sourced values and conditions. Read relevant linked owners before replacing a rule with local improvisation. Decide truly missing design facts consistently with Canon and the DM's intent, and mark them apart from established events in the return. **Done when** each opening dependency and reused rule has a retrieved source passage or a stated missing-fact design decision, and every reachable predecessor branch has an entry state rather than an assumed victory.
3. **Choose the card.** Select the kind's card against the entry state, Thread and requested purpose. Keep the choice in Prep's planning material, outside Scene properties and spoken Narration. Without Prep, include it in the return for later charting. Apply the kind's craft and the Scripting the Game rules below. If a row supplies a card, use it unless it conflicts with the established fiction. When you correct it locally, return the reason. **Done when** the chosen card, pressure or turn, table-time allotment, Spotlight and next destination fit the exact kind and chart or bounded standalone brief.
4. **Resolve the cast.** Reuse the first fitting source in `AGENTS.md` order, which runs from the Wiki to the 2024 SRD through `dnd5e-srd-api`, then to official or existing published/homebrew material through the harness's web search and fetch tools, then to novel design. Read the full facts on the page itself before using them. Create only missing owners through the matching skill: `npc-design`, `creature-design`, `location-design`, `item-design`, `faction-design`, `vehicle-design`, `spell-design` or `lore-design` as needed. Supply Canon, local purpose, Party facts, intended paths and enclosing operation. Wait for complete pages and touched paths before relying on them. Take an NPC's fighting statistics from its linked Creature page, which is separate from its identity page. Verify every archived-Raw path used as provenance against a real readable file. Copy its exact path from retrieved evidence instead of deriving it from an entity's name. External rule sources go in a body attribution. The `sources` property lists only archived-Raw provenance paths. When no archived Raw applies, use `sources: []`. **Done when** every needed named entity and rules owner exists, its links and provenance paths resolve, and each new page has a content link in from the Scene or another relevant page.
5. **Write the runnable page.** Fill `<vault>/templates/Scene - <Kind>.md` at `<Campaign>/Sessions/Session <N>/Session <N> - <Scene title>.md`. Keep every required property, the exact `##` headings at their original depth and in order, and every required callout type. Remove template guidance, and keep optional structure only where it has content. Optional subheadings organise content inside that spine and leave the required sections in place. Use `type: Scene`, the exact `kind`, a useful summary and verified archived-Raw provenance in `sources`. Link the page from Prep's Scene Chart when present and update the row's planning notes or Clue routes where the Scene changes them. Put all table-use facts on the page, including who wants what and by which means, how each side responds, useful spatial relationships, pressure triggers, accessible choices and consequences. Each hidden truth has a concrete way to learn it. Rule uncertain actions with Ability (Skill), DC, action or time cost and both results. For a save, give the ability, DC and effects, and for a contest, give both sides and ties. Sensible actions without real doubt simply work. Keep required conclusions discoverable through three independent routes across the chart or standalone Scene. A failed check changes cost or position and leaves a way forward open. Use the Encounters section below when physical danger is present. Creature statistics remain on their owner pages. The Scene exposes them through resolving `![[Creature#Statblock]]` section embeds. **Done when** the filed page matches the template's actual spine and the DM can adjudicate each offered action from its sourced rules and rendered owner embeds.
6. **Compose Narration.** Once the DM-side facts exist, invoke `theatre-of-the-mind` with each callout by title, its Scene kind, actual viewpoint and entry condition, spatial facts and the owner/source pages it may read. Request callout-only authoring and explicitly defer child tooling to this operation's final gate. Preserve the template's title. Hook, Development, Cliffhanger and Climax use `Opening`, and Resolution uses `Closing image`. The Narration skill's corresponding recipe defines construction, length and its final check. Put NPC or Creature entering callouts under Play or Encounter, titled with the subject's name. A major Revelation gets its own conditional callout. If preceding alternatives change what is visible, write the selection condition in DM notes outside each variant's callout and state which variant the DM reads. When an established result settles an unplayed cut of time or space, place a `Transition` immediately before the destination's opening or closing slot. Unresolved travel choices remain open to the Players. Check the filed prose against the Narration skill's applicable final-check items using its actual words, then against every entry that can select it. Repair mismatched carriers, companions, possessions or positions. **Done when** every required spoken slot is filed, its applicable Narration checks have textual evidence, each branch's visible facts are true on its own condition, and live events stop where the Players can respond.
7. **Resolve exits.** For Hook, Development, Cliffhanger and Climax, fill the template's `## Outcomes`: each materially different result states its trigger, the concrete World change and a resolving destination link on the chart. Cover offered approaches, failure, withdrawal, waiting or refusal where they change the situation. Give the receiving Scene the resulting knowledge, positions, ownership, conditions, resources and clock state it needs. Results share a destination only when its entry works for each of them. A standalone Scene without a chart states its next pressure, trigger and handed-on state in the same rows, ready for charting, and links only to pages that exist. Resolution instead holds its Climax-conditioned payoffs, reactions, rewards and next-Session carry-forward in `## Play` and `## Threads`, as its template requires. Proposed deaths, captures, rewards and Thread changes remain conditional Prep, not updates to current Canon. **Done when** each prepared result has a usable successor state or Session-ending carry-forward and every existing receiving page accounts for it. Return pending entry variants to the caller for pages not yet authored.
8. **Cold read.** Read the Scene and render its linked embeds as the DM would with no sourcebooks or chat available. Run the kind's completion criteria, then trace each entry through its options to an exit. On the way, confirm that names resolve, that rules and statistics are available, that pressure advances on stated triggers, that critical information has multiple routes, that the Narration fits the entry, and that no result depends on the Party accepting a predetermined answer. Compare the finished heading spine with the actual template, every copied provenance path with its file, each reused ruling with its owner passage, and Balance numbers with the `bun run cf -- encounter-budget` output and Party evidence. Correct mismatches in the Scene and its local Prep material. Return any required chart recomputation to its owner. **Done when** the kind's criteria hold in the actual page, every entry and exit is runnable, every source and template comparison agrees, and each cited table-use fact is on the page.
9. **Close the operation.** Follow Completion below. **Done when** the index, page-gate and log cycle is observed for standalone work, or the explicit composing caller has all artifacts, touched paths, conditional states and remaining findings needed for its single completion cycle. A child return is not a claim that Prep or Push has completed.

## Scripting the Game

Mike Pondsmith's *Scripting the Game* is the pacing method, and it takes precedence over a loose pool of potential Scenes. A Session runs one Hook first, alternating non-action Developments and physical-risk Cliffhangers in the middle, then one Climax and its Resolution. After an action Hook the middle starts with a Development, and after a cerebral Hook it starts with a Cliffhanger. The final middle Scene can lead directly into the Climax. In a compact Session with no middle Scenes, the Hook leads straight into the Climax.

Use approximately thirty minutes per Scene and the actual chart's Minutes allocation. The Hook, Climax and Resolution reserve about ninety minutes together. Middle Scenes fit the remaining Session length, not a quota. A kind's shorter contest or closing image can leave room elsewhere. In-world clocks state their own units separately from table minutes. An uncertain result changes the next Scene's entry. The chart orders pressure and opportunities, and victories, accepted jobs and routes remain open.

## Encounters

Take 2024 XP numbers from `bun run cf -- encounter-budget` in two cases. The first is a Cliffhanger or Climax with Creatures the Party might fight, including a violent fallback to negotiation. The second is an action Hook borrowing Cliffhanger craft. The command classifies Creature spend only. Choosing the opposition and judging other dangers remain your job.

1. **Budget.** Establish the participating PCs from current Sheets and incoming conditions, excluding anyone unable to participate and explaining that exclusion. Use character level across classes. Select Low, Moderate or High to match the row and the kind's craft. Run `bun run cf -- encounter-budget --help`, then print that party's budgets:

   `bun run cf -- encounter-budget --levels <each participating PC level>`

   Apply sourced House Rules first. Take every total from the CLI output, never from a table, memory or hand arithmetic. The CLI adds a +1 combat offset to each recorded level (this Party fights above the calculator). Pass sheet levels as recorded, without the offset. **Done when** the contributing PCs and levels match the entry and the CLI has printed that party's Low, Moderate and High totals.

2. **Spend.** For each opposing type, take `count`, CR and XP from its retrieved Wiki or 2024 SRD statblock (Canon, then `dnd5e-srd-api`, then published material). Pass those values to the same command directly, without a creature lookup database:

   `bun run cf -- encounter-budget --levels <levels> --target <low|moderate|high> --creature "Name,CR,XP,count"`

   Repeat `--creature` per type. Equal to a band ceiling is that band. One XP over High is Beyond High. The bands follow the 2024 rules alone, so leave out the 2014 monster-count multiplier and the Easy/Medium/Hard/Deadly thresholds. Read the printed band and any `Vs` delta, then decide whether that spend is the right fight. When Canon fixes an over-budget force, keep the CLI's label, state the excess, and give playable avoidance, escape or objective routes rather than claiming a balanced fight or changing recorded statistics. State when reinforcements arrive and whether waves overlap. Account for every distinct opponent that can participate, without counting the same Creature again merely because its tactics change. Separate mutually exclusive opposing forces so each possible fight has its own run. A duel uses the PCs actually fighting. **Done when** each comparison is the CLI's printed totals for that force and the page's description of danger matches the planned contest, including what XP does not cover.

3. **Expose the plan.** Copy the CLI's Encounter Balance lines under `### Balance` in a Cliffhanger's `## Encounter`. In a fighting Climax or Hook, use `### Encounter` under `## Play` with `#### Balance`. Name `bun run cf -- encounter-budget` as the budget source, the participating PCs, and the Creature pages supplying XP. Write the encounter inside the current Scene template's sections as they stand. Include quantities, deployment, battlefield features, opposition objectives, opening tactics, adaptations and break/escape conditions. Embed each fought Creature as `![[Creature#Statblock]]` at this Encounter and link it elsewhere. Resolve named NPC combatants to their Creature owners. XP measures Creature spend against the Party budget only: state how terrain, surprise, allies, depleted resources, hazards and objectives change the actual danger. **Done when** the DM has the entire playable opposition, every XP figure traces to the CLI output and a retrieved statblock, and the page states what the XP comparison does not measure.

A creature-free chase or hazard has no monster XP to spend. Keep any template-required `## Encounter` and explain why XP balance does not apply. Calibrate its actual danger to the Party with sourced DCs, damage or conditions, action costs, duration, escape routes and resource demands. The kind's skill supplies the contest engine. A non-action Development or Resolution remains non-action, so leave unplanned fights out of it.

## Completion

### Standalone

Review the installed CLI help before using commands:

```bash
bun run cf -- check --help
bun run cf -- index --help
bun run cf -- log --help
bun run cf -- encounter-budget --help
```

From the repo root, regenerate the generated index and run the page gate (`AGENTS.md` **Gate scope**) given the Scene and every page this run touched, applying mechanical fixes without changing Canon:

```bash
bun run cf -- index
bun run cf -- check --fix "<page path>" "<page path>"
bun run cf -- check "<page path>" "<page path>"
```

Treat gate findings as unfinished authoring. Classify each reported finding, apply available mechanical fixes, repair the remaining content while preserving Canon, and rerun the page gate after the repairs. Grammar and style findings require sentence-level revision. Listing them in the reply leaves the work unfinished. Keep every layer enabled and continue until the page gate reports `ok: 0 findings`, warnings included. A `--layer` filter is diagnostic only and never counts as completion evidence. For an assigned filesystem root, add `--vault "<wiki>" --root "<root>"` to index, check and log, and `--templates "<wiki>/templates"` to check.

Append the operation log only after the latest page gate has reported `ok: 0 findings`. Any finding keeps the operation unlogged and the repair loop active. The one completed entry lists every touched content page by its vault-relative path:

```bash
bun run cf -- log --world "<World>" --op create --title "Author Session <N> <Scene title>" --page "<World>/<Campaign>/Sessions/Session <N>/Session <N> - <Scene title>.md"
```

Repeat `--page` for Prep and all dependent pages actually changed. Direct single-Scene work outside an enclosing Prep uses `create`. A composing operation logs under its own operation. Generated `index.md` and `log.md` belong to the CLI. Single-Scene work preserves `hot.md` and played Session records. Full Prep rewrites `hot.md` and runs Push itself.

Return the Scene and dependency paths, substantive design decisions and their grounding, conditional carry-forward, and the observed gate/log result. Page findings remain work in progress, never blockers. An unavailable prerequisite is a blocker only when failed tool or capability output establishes it and supported remedies have been exhausted. Report that evidence and the exact missing prerequisite, and leave the operation unlogged. Complete when the page and all dependencies are runnable, the index is current, the page gate reported `ok: 0 findings`, and the log entry exists.

### Composed

When an explicit caller runs the final operation, return the authored Scene, owner pages, changed Prep material, every touched path, design decisions, conditional incoming/outgoing states, and any tooling findings. Give the caller the actual pending destination paths and entry variants, not name-only promises. The caller regenerates the index and repairs findings through the page-gate loop above over every touched path. Once the gate prints `ok: 0 findings`, the caller records one entry for all touched pages and performs its remaining hot/Push steps. Keep those duties with that caller rather than issuing a separate child log. Complete when every local craft and cold-read criterion holds and the caller has the full return needed to finish end to end. A handoff with a failing gate is still an incomplete operation.

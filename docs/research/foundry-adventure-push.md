# Foundry Adventure Push

Researched 2026-09-29 for `bun run cf -- push` (issue #20, ADR 0008). Everything under "Verified" was read from the installed Foundry v14 build 367 (`common/`, `client/` and `dist/` in the app), the installed dnd5e 5.3.3 system, `@foundryvtt/foundryvtt-cli` 3.0.4, or observed by running code. "Not verified" says what could not be.

## Verified

- **Adventure import keeps IDs and updates in place.** `Adventure#prepareImport` splits each embedded collection into documents whose `_id` already exists in the Foundry world (updated) and the rest (created). Creation uses `keepId: true`. Updates use `updateDocuments` with `diff: false, recursive: false`, so an updated document is replaced whole: a re-imported Foundry scene loses the DM's token moves, and a re-imported journal loses ownership the DM granted live. The import asks the DM to confirm before overwriting. This is what ADR 0008 relies on, and it means the Push skill must reapply ownership after a re-import.
- **A pack with no `system` drops its Actors and Items.** `Adventure.fromSource` empties `actors` and `items` for a pack whose metadata has no `system`. The module's pack therefore declares `"system": "dnd5e"`.
- **Adventure documents are stored whole.** The CLI's `compilePack` writes one database entry `!adventures!<id>` whose `actors`, `items`, `journal`, `scenes` and `folders` arrays hold the full documents, embedded Items included (its hierarchy table has no entry for adventures, so nothing is split). `extractPack` returns the same JSON, which is how the tests unpack a built pack. `compilePack(src, dest)` is the programmatic API; it needs `classic-level`'s native build, so `pnpm-workspace.yaml` allows it.
- **Foundry's own data models run in Node.** `common/server.mjs` imports without a server; with `CONFIG`, `game.model` and `game.system.grid` stubbed, `new BaseAdventure(data, {strict: true})` validates every embedded Actor, Item, journal, Foundry scene and folder, and the module manifest validates with `foundry.packages`. `test/push/foundry-models.test.ts` does this and proves the check bites (a bad ID and a bad wall are rejected). It skips where Foundry is not installed.
- **v14 scenes have Levels.** A Scene's background lives on `levels[]` (`background.src`), and a new Scene gets the Level `defaultLevel0000`. Walls, lights and tokens carry a `level` or `levels`. The Universal Battlemap Importer (`moo-man/FVTT-DD-Import`) builds the same shape: one Level with `_id: "defaultLevel0000"`, walls and lights with `levels: [id]`.
- **Universal VTT shape** (Arkenforge spec, and what the importer reads): `resolution.{map_origin, map_size, pixels_per_grid}`, `line_of_sight` and `objects_line_of_sight` as polylines of `{x, y}`, `portals[].{bounds: [{x,y},{x,y}], closed, rotation, freestanding}`, `lights[].{position, range, intensity, color, shadows}`, `environment`, and a base64 `image`. All lengths are grid squares. The importer maps a light to `dim = range x 5 ft`, `bright = dim / 2` and colour `#` + `color.substring(2)` (Dungeondraft writes `aarrggbb`). Push copies those mappings.
- **dnd5e conventions.** From the system's compendiums (`actors24`, `monsterfeatures24`, `equipment24`): an NPC's natural attacks are `weapon` Items with `type.value: "natural"` (354 of 436 weapon Items on NPCs), traits are `feat` Items with `properties: ["trait"]`, AC is `calc: "natural"` with `flat`, movement values are strings, a recharge is `uses: {max: "1", recovery: [{period: "recharge", formula: "5"}]}`, and an attack activity with `attack.flat: true` uses `attack.bonus` as the whole to-hit (`AttackActivity#getAttackData`). Damage parts add no ability modifier by themselves, so the printed `+2` is written as `bonus: "2"`. Loot Items have no `attunement` field (a check against the compendium found this before it shipped).
- **Key-path conformance.** Every key path Push emits in an Actor, embedded Item or Item is present in the system's own compendium data (`test/push/dnd5e-shape.test.ts`, skipped where dnd5e is not installed; it copies the packs before opening them).

## Approximated

- An attack's to-hit is a flat printed number, not proficiency plus ability; only the first hit's damage, and unconditional "plus" damage, become damage parts. A rider that needs Advantage or a condition stays in the description.
- Save-based actions (breath weapons) and Multiattack are features with text and a utility activity, not `save` activities.
- Languages, resistances and immunities outside the dnd5e lists (a qualifier such as "nonmagical") go to the trait's `custom` field.
- Item types come from the page's `**Kind.**` line: wondrous, ring, rod, wand, armor and shield map to `equipment`, weapons to `weapon`, potions and scrolls to `consumable`, and anything else to `loot`. Armor and weapons get a generic `type.value`, not stats.
- Walls come from the Universal VTT file as plain walls plus doors; windows, secret doors and terrain walls are not distinguished.

## Not verified

- **A headless import.** Foundry refused to serve without a valid licence: `dist/core/license.mjs` verifies a signature over `{host: os.hostname(), license, version}`, and the DM's `Config/license.json` was signed for the host `macbook.lan` while this machine is now `Nicks-MacBook-Air.local`. Its Foundry logged the same failure on 2026-09-28. Re-signing means sending the DM's licence key to foundryvtt.com, which was outside what was authorised, and overriding the hostname to make the old signature verify would be working around the check, so neither was done. To finish: run Foundry once from its app (it re-signs), copy the new `Config/license.json` into the test data path, start `node main.js --dataPath=<test> --port=30444 --noupnp`, create a dnd5e world, enable the built module, and import the Adventure through the UI or `game.packs.get("<module>.adventure").getDocument(id).then(a => a.import())`. Check that Actors, Items, journals and the Foundry scene appear, then push after a Wiki edit and confirm the same IDs update.
- The dnd5e `system` blocks are checked by shape, not by the dnd5e data model, which is client-only code.

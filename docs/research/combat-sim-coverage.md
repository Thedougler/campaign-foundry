# Combat-simulator coverage audit

This audit maps the documented legacy capabilities and DM workflows in Campaign-OS `combat-sim` and `dndsim` to campaign-foundry (CF) today. It is evidence for the engine-design ADR, not a plan to build them. CF has a 2024 XP-budget calculator, but no combat simulator.

**Sources.** [Pinned JS README (`b19729f`)](https://github.com/Thedougler/campaign-os/blob/b19729f63e5e634fb6959a828ad723b93565e5d1/utils/scripts/combat-sim/README.md); [dndsim README](https://github.com/Thedougler/campaign-os/blob/main/utils/dndsim/README.md), [DIVERGENCES](https://github.com/Thedougler/campaign-os/blob/main/utils/dndsim/DIVERGENCES.md), [CLI source](https://github.com/Thedougler/campaign-os/blob/main/utils/dndsim/src/dndsim/cli.py), [knob vocabulary](https://github.com/Thedougler/campaign-os/blob/main/utils/dndsim/src/dndsim/rules/dnd5e_2014/knobs.py), [revival plan](https://github.com/Thedougler/campaign-os/blob/main/docs/plans/dndsim-revival.md), [tuning runbook](https://github.com/Thedougler/campaign-os/blob/main/vault/refs/runbook-encounter-tuning.md), [combat-profiles skill](https://github.com/Thedougler/campaign-os/blob/main/.claude/skills/combat-profiles/SKILL.md). This inventory and its three Raw Source pages are [in Notion](https://app.notion.com/p/3f70216635ec81238227c3dae3d23f89). CF evidence is linked to source files below.

**Status vocabulary.** `present` = the capability exists in CF; `partial` = related calculation/workflow exists but does not provide the legacy behavior; `missing` = no corresponding capability found; `intentionally changed` = explicit CF rule differs; `historically never operational` = legacy documentation declared it, but source documents say it never worked. Legacy surface: `JS-implemented`, `dndsim-CLI`, `dndsim-source-only` (module exists, not exposed by documented CLI), `specified-only` (documented design without a working version), or `never operational`.

## CF encounter-budget overlap and workflow callers

`encounter-budget` is the only combat-adjacent calculation found in CF: [2024 XP thresholds and CR-to-XP mapping](../../src/encounter/xp-budget.ts) plus [`cfcli encounter-budget`](../../src/commands/encounter-budget.ts). It adds participating PC budgets using a configurable +1 level offset and totals creature XP. It returns Low, Moderate, High or Beyond High, and prints text or JSON. It does not select opposition or measure terrain, hazards, surprise, depletion or objectives. Spend/band rows are `partial`, not simulator parity. The Encounter guidance in [scene-pages.md](../../docs/agents/scene-pages.md#encounters) calls the calculator and records its balance output. Skill search found callers in `cliffhanger-scene`, `prep-session` and `statblock-design/references/tuning.md`. The searched workspace had no requested `creature-design/references/tuning-and-budget.md` path or matching `climax-scene` call. The tuning reference handles XP budgets, not Monte Carlo simulation.

## Design-relevant findings

- Both simulators were intended as more than win-rate calculators: roster modeling, per-PC diagnostics, count/corpus screening, tuning and persistent learning workflows are distinct capabilities.
- The JS simulator had three verbs (`sim-combat`, `profile`, `parse`), but most powerful behavior used `sim-combat` flags for sweeps, scenarios, goals, genetic tuning, adaptive stopping, reports and audit controls.
- dndsim exposes `sim-combat`, `profile`, `parse`, `lint`, `sweep-corpus`, `sweep-count`, plus `convert-srd` in CLI source; sensitivity, goals, evolution and knobs exist as modules, not documented CLI commands. Don't mistake source modules for a user-facing complete workflow.
- JS `--death-saves` was declared but simulation code never read it. dndsim runs ordinary death saves, but its documentation notes missing critical-hit double failures and massive-damage instant death.
- JS spell-fence support is a retired path with no working support for the real spell corpus. dndsim's revival plan specified prose parsing, but does not prove a completed parser. Spellcasting coverage remains absent because neither source has a proven completed spell parser.
- The Python mutation set intentionally has only seven live knobs (AC, HP, to-hit, flat damage, dice step, multiattack, speed); save DC, recharge/legendary counts, regen/aura, start band and percentage reduction were explicitly deferred because the source has no compiled interfaces for them.
- `DIVERGENCES.md` records numeric-string acceptance, validation timing, resolved fixed initiative order and lair-action activation. These rules distinguish parity and evidence from coding details.
- Spatial combat was approximate bands, not a tactical grid: formations, range, movement, opportunity attacks, AoE caps and aura bands were modeled without full geometry.
- CF has only the 2024 XP-budget calculator and authored encounter workflow today; it has no legacy combat simulation, profile, sweep, goal scoring, mutation, evidence ledger or narrative fight output.

## 1. Inline-first run-guide craft

- source: `.claude/skills/prep-session/references/run-guide-spec.md` (found); `wiki/sessions/session-06-run-guide.md` (found, 55.9KB — copied as structure-only condensation at `wiki/sessions/session-06-run-guide.structure.md`: dashboard + card headings + Scene 1 and Scene 4 as example cards)
- destination: `prep-session` + Scene skills + templates; findings say keep CF's fixed Hook→…→Resolution chart but allow an optional middle menu
- load-bearing:
  - Definition/test: "A run guide is a **scannable operating document the DM runs cold at the table.** Not a script, not prose. Judge every line by one test: *does this help the DM run the next beat without opening another file?*" The failure mode to design against: "a guide that is really a table of contents pointing elsewhere."
  - Three zones: Dashboard → Scenes → Reference. "Everything here is a table or a callout — no prose paragraphs" (dashboard); reference material is looked up "by need, not by scroll position."
  - Dashboard: Session Snapshot = 4-row table (**Party is / Last break / Hottest pressure / Table time**), "Do not infer where the party will go." Thread Strip: `| Thread | Right now | If ignored | Tick they'll see |`, max 5; "A clock here is *pending pressure*, not a canon write"; "Good tick: 'three more soldiers arrived on the morning ferry.' Bad tick: 'tensions are rising.' If the DM can't show it at the table, it isn't a tick." NPC Bench: table handles, cap ~8, 3 columns (Name/Grab when/Handle) or 4 (+Wants now); handle = "the one line that lets the DM play them instantly." Day Tracker for sessions spanning 2–3 in-game days: one row per thread, one column per day.
  - Scene card template fields: `### [Scene Name] *(Thread Name)*` header; `*Pull: [PC(s)] · Register: [social/combat/revelation/exploratory]*`; `*Available: [any time / Day 2+ / when the party does X]*`; one image embed; `> [!read-aloud]` (2–4 sentences, "every sentence past the fourth is the DM talking to themselves"); **What's true:** one paragraph; **NPC — [Name]:** handle + *Wants:* (present tense) + *Reveals:* (what and under what pressure); `> [!skill-check] Ability (DC N)` with Success AND Failure each revealing something ("never 'nothing happens'"); **If engaged:** / **If ignored:** / **Hook out:**.
  - Scene card rules: "Default 3–5 live scenes; max 7 total. More than 7 = multiple sessions." "No card depends on the party having chosen another card first" — dependency (cannot work without prior card) vs trigger (activates when fiction reaches a state) distinction. "Every card has an *if ignored* consequence… Ignored ≠ deleted — the pressure *moves*, it doesn't vanish. Say where it goes." "Mark the genuinely cuttable scene `*(optional)*` — and make it the most fun one." Multi-beat scenes use H4 subheaders inside one card. Inline stat line format: `**Handler (×3):** AC 14 · HP 22 · +5 to hit, 1d6+3 · poison dart DC 12 Con · *Tactic:* skirmish, break sightlines, never fight to the death. → full block: [[...]]`.
  - Zone 3 reference sections: Secrets & Clues (5–10 facts "kept **unassigned** — give each to the first action that earns it"; critical clue reachable three ways); Stall Hooks (table: Hook / Comes to / Pulls toward; "Pick one — don't throw all at once"); Spotlight ("attach them to a scene that already exists. Never manufacture a scene whose only purpose is the spotlight"); If They Surprise You (4 steps: place the request in the world → give one competent local who wants one small thing → attach one live pressure from the Threads table → let the choice stand; "Never have a second NPC repeat the same hook until they comply"); Possible Cliffhanger ("name the highest-tension state(s) worth recognizing *if* they happen"); Capture For Next Time (which scenes fired/ignored and where pressure moved, clocks to advance, whose spotlight landed); Context Read (pages read during prep).
  - Quality gate (checklist): one-file test; run-cold test ("could the DM run each scene card with the rest of the wiki closed?"); scope test (max 7 cards, max 3 in-game days); dashboard fits one screen; thread-organized not day-organized; every scene has if-ignored; no scene depends on prior player choice; every clock tick observable; images max 1 per scene card at top, none in dashboard.
  - S06 example demonstrates: fixed scenes 1/2/3/7 + scenes 4–6 "Optional, any order… Run the ones they reach; skip the rest — each is self-contained"; dormant threads still get rows ("Advances off-screen… Surfaces if the party reaches open water").
- skip-from-this-file: Obsidian wikilink/embed syntax, `ttrpg-visual-aids`/`openrouter-image-gen` plumbing, frontmatter hook, commit conventions.

## 2. Roleplay Concept mashup + Quote + proactive objective

- source: `.claude/skills/prep-npc/SKILL.md` (found); `.claude/skills/prep-npc/references/NPC.md` (found); `.claude/skills/ttrpg-llm-wiki-init/references/PREP.md` (found-at — findings' path `ttrpg-llm-wiki-init/references/PREP.md` is actually under `.claude/skills/`)

- load-bearing:
  - Mashup formula (PREP.md § Roleplay Method): `[unexpected animal/archetype/vibe] + [pop culture character/persona]` — examples: *owl Obi-Wan Kenobi*, *rat grandma Scarface*, *southern golden retriever lawyer*, *burned-out vice principal Voldemort*, *yoga instructor who is also a hitman*. "The mashup is the character's **operating system** — not look, not job, not backstory. Every choice flows from it. The two halves must create tension (warm AND territorial, menacing AND exhausted). If a line could belong to any character, rewrite it." Must "land in one read" — bad: "A complex figure torn between duty and ambition."
  - Output order (prep-npc SKILL): **Roleplay Concept** first line above everything; **Quote** mandatory immediately after — one in-character sentence, "If this quote could belong to any NPC, rewrite it. Each sentence gives the DM something usable."
  - Toy fields (5, frontmatter + synced `## Toy Chest` body table): `primary_goal` — "a vector, not a state" (✓ "Accumulate enough to retire before the audit." ✗ "Is ambitious."); `consistent_method` — "a gimmick, not a personality. Doable at the table in 5 seconds"; "Cut everything after an em dash that analyses rather than describes" (✓ "Feigns helplessness, then names his price. Never in writing."); `active_problem` — "The situation only. A problem for THIS NPC, right now. Not their response to it," not a countdown; `performance_hooks` — "Roleplay Concept mashup + one speech pattern. Nothing more"; `link_of_relevance` — required, one sentence, "If you can't answer this, the NPC isn't ready."
  - Voice & Delivery block: speech patterns/tics; "2–3 actual lines the DM can say at the table"; physical mannerisms; "Emotional default + what cracks it." Performance hooks written as "felt actions, not clinical instructions." Voice lines as "performance notes, not personality adjectives": ✓ "Pauses mid-sentence to recalculate"; ✗ "Calculating and precise."
  - Gimmick rule: "A gimmick is a launchpad, not a ceiling. One-time NPCs can live entirely in the bit… Recurring characters need to eventually surprise even you… A recurring character who never develops past their gimmick becomes annoying, not memorable." Skip mashup for mindless beasts and non-speaking entities.

  - Villain layer (NPC.md): Three Villain Questions — want (specific, not "power"), fear ("the crack in the armour — emotionally and mechanically"), tell ("one physical habit… that makes them recognisable"). Mechanics: escape mechanic (recurring villains need a way out), personal shield (feels invulnerable until players solve it), optional monologue trait (speak without using action, include a suggested line). Post-statblock tag: **Personality / Motivation (what they want right now in this encounter) / Escape Condition.**

## 4. ttrpg-writing standards (anti-slop + two-mode voice)

- source: `.claude/skills/ttrpg-writing/SKILL.md` (found); `references/dm-reference-standards.md` (found); `references/brennan-voice.md` (found); `references/UNIVERSAL-TOYS.md` (found)
- destination: `theatre-of-the-mind`, `humanizer`, scene skills, `docs/intent/`; several checks are lintable
- load-bearing:
  - Mode selector: DM-facing (reference) vs player-facing (prose) — "the techniques are opposite and applying one to the other context actively degrades the output"; mixed pages "apply each mode to its section separately." DM reference contract: "Every sentence must give them something to say, do, or decide — nothing else."
  - Anti-Slop Pass (all checkable): **Deletion Test** — "if removing it doesn't eliminate a mechanical fact about the world, delete it" ("rusty" keeps, "imposing" cuts); **Negation Limit** — negative constructions capped at two per page, rewrite as affirmatives; **Banned structures** — contrastive reframes ("It wasn't just cold…"), trite escalation ("Little did they know…"), "the kind of silence that has teeth", atmospheric rhetorical questions; **No Portentous Withholding** — "'He's terrified of the guild' is better than 'those who know him say he carries old debts'"; **No Negative-Space Writing** — "'She didn't answer' → 'She looked at the floor'"; **Two-Paragraph Rule** — after any atmospheric sentence, next sentence must be plain and mechanical; **No Invented Stakes** — nothing not in source or brief. Enforcement stance: fix violations silently on touch; "the task is always to leave the page better than you found it."
  - Brennan voice rules: consequence first ("Action and result are one beat. 'She counterspells. She drops a sixth-level slot. It doesn't work.' Not 'You watch her try to counterspell.'"); "Short sentences carry weight… The gap does work"; "Specificity is the emotional hit"; **reveal retroactive stakes** after dramatic outcomes ("say what would have happened the other way"); **NPC rhythms, not personalities** (impatient authority = clipped directives; find the operating rhythm before writing any line). Avoid: atmosphere before action, "you see X" when "X happens" works, softened consequences, narrating player feelings, labeling things anomalous. Voice governs prose only — "Applying voice to a stat line wastes the DM's scan time."
  - Villain speeches (brennan-voice.md): "Brennan's villains argue. They don't threaten." Construction: identify what the PC values → build the villain's sincere counter-belief (thought through, not performed) → target this specific character → end on the thing that can't be argued back. "Don't write menace. Write conviction… if you poked holes in it before the character finished speaking, it isn't good enough yet."
  - Combat narration: "Name the mechanical event, then inhabit it"; build dice tension explicitly ("You need an 11 or higher. It's a coin flip."); after big success reveal what almost happened; "Homebrew in service of the moment" (rename spells for ownership); "Repetition earns its keep… When once won't land what three will, use three." Tone: comedy and drama both genuine, same breath; "Heavy beats land harder after something funny — don't smooth the transition."
  - DM reference standards: OSE — terse delivery ("more than two sentences… written wrong"), **point-first** (`Iron Door: Locked, rusted hinges. (DC 15 Athletics to force open)`), typographic encoding (bold = threats/NPCs, italic = magic/treasure, plain = environment), objective third person (never "you" in DM reference). Bryce Lynch — read-aloud as optional service (never mandatory boxed text; ≤4 sentences); evocative not exhaustive (2–3 defining sensory details: sound/smell/texture/temperature/something-wrong, not furniture inventory); non-linear maps (loops, varied elevation, loud-fast vs quiet-slow routes); no generic magic items (physical description + exact activation + one hook). Skerples — transparent DM notes (authorial intent stated); **Rule of Threes** (primary intent + max 3 sub-points). Alexandrian — Three Clue Rule with explicit listing in DM notes (Conclusion / Clue 1/2/3 across different nodes). Scanability test: "what do I do right now?" in three seconds; no paragraph >3 sentences in DM content.
  - If-Ignored Requirement + tick test: "Write it as a concrete, observable consequence." Good: "the commission assembles and departs; the wreck is not empty when they reach it." Bad: "tensions rise. (Unshowable. Rise how? Who notices?)"; "if you can't describe a single visible, in-world change… it isn't concrete enough."
  - UNIVERSAL-TOYS: clock template (Day 1 visible-but-ignorable → Day 3 faction involvement → Day 5 point of no return; "Players do nothing → things change anyway"); Toy Chest targets (6–10 NPCs, 3–5 factions "each with an active off-screen action", 2–3 locations, 3–5 clocks already running); **Session Zero five questions** (become / afraid of losing / who they love / personal failure / "red button"); theatrical mechanics — Degrees of Success (3-tier DC 10/15/20, "Failure must move the story forward, never stall it"), Mechanical Shenanigans (one per session: advantage/reroll for "a meaningful character cost"), Box of Doom ("Declare DC and both outcomes publicly before dice fall"); stakes-first narration (risk → what makes stakes legible → environment only if it affects stakes; ❌ "You enter a large stone chamber" ✅ stakes example).
  - Callout craft: four types only (`[!read-aloud]` / `[!dm]` max 3 sentences verb-first / `[!mechanic]` trigger-then-consequence / `[!check]` DC + fail/success outcomes) — "Wrong types break that scanability."
- skip-from-this-file: publish contracts/paired pages, `[!contradiction]`/`[!lint]` audit markers, PostToolUse hook, wiki-index checks, `rg` path verification, response-format defaults.

## 5. Faction/thread simulation modes

- source: `.claude/skills/prep-faction/references/faction-simulation.md` (found); `.claude/skills/world-update/SKILL.md` (found); `.claude/skills/world-update/references/update-workflow.md` (found, copied unread — full ritual detail)
- destination: `faction-design` agenda ticks + post-ingest hot rewrite; findings call the planning/advancement split the missing piece
- load-bearing:
  - Three modes: **Planning** (session prep; "Identify likely offscreen pressure… but do not write canon changes unless the user explicitly asks"; output = table `| Thread | Current state | Likely offscreen move | What becomes visible | Source |` in conditional language — "If unopposed, they will…"); **Advancement** (writes canon; propose tick list → confirm unless autonomous → resolve per thread → "Write the result to every page that now owns changed state"); **Review** ("summarize current state and likely next moves. Do not write.")
  - Canon discipline: read the owning page before describing state; "Treat DM design notes as intent, not canon, unless a session record says they happened"; "Do not start a clock unless its trigger has fired"; "Do not invent NPC knowledge"; "A low or stalled result should still change pressure, information, exposure, or positioning. 'Nothing happens' is rarely useful."
  - Eligibility: qualifies if party engaged it, a faction has reason to react, the party ignored a known pressure, or a visible clock is near. Skip: never-encountered distant factions, background lore without pressure, unfired triggers, "secrets that would only advance because they are dramatically convenient."
  - World-tick d20 bands: **1–5 Setback** (fails/backfires, pressure shifts visibly) / **6–15 Partial** ("Real progress with friction, exposure, cost, or complication") / **16–20 Full** ("Goal is accomplished; world state changes cleanly").
  - Collisions: if two factions act against each other, "resolve the collision instead of advancing both independently" — check resources/leverage, proximity, knowledge, timing, temperament, player interference; quality check: "resolved once, not double-counted."
  - Urgency → placement: low = DM reminder/clue list; medium = scene-menu candidate; high = scene-menu priority; critical = "Strong Start candidate" ("Goal resolves this session if uncontested").
  - Write targets: situation file, faction page, NPC page, place page, hot cache — "Do not bury changed state only in `hot.md` or a run guide. The owning page must change too."
  - world-update SKILL: core question everywhere — *"If the party had done nothing, what would have changed anyway?"* "The party is one variable — not the engine." Triage HOT/WARM/COLD by engagement: HOT = full treatment; WARM = "one action and one visible ripple the party could notice"; COLD = "one sentence of offscreen movement and a hook that strengthens. As cold threads accumulate… their hooks escalate from whisper to collision."
  - Clock advance discipline: read situation file trigger → did it occur? yes → advance **with citation** `[from: {situation-slug}]`; "**Clock fills** → **flag to DM, do not fire.** No triggered event executes without DM confirmation"; no trigger → document minimum passive activity anyway ("Factions don't pause").
- skip-from-this-file: Obsidian templating, `roll.sh`, context-loading order, commit steps, frontmatter repair rules.

## 7. Narrative islands / street banks

- source: `.claude/skills/prep-island/references/ISLAND-TEMPLATE.md` (found); `wiki/narrative-islands/calveno-street-encounters.md` (found, 16.2KB — copied as structure-only condensation at `wiki/narrative-islands/calveno-street-encounters.structure.md`)
- destination: optional Scene bank pages for Settlements; `plan-session` riffs; partial coverage via dungeon/location design
- load-bearing:
  - Definition: "An island is a **situation with a ticking clock and a dramatic question the party answers through play.** Not a meeting. Not an errand." Diagnostic: "Can you state the dramatic question in one sentence? YES → it's an island. NO → it's a task, an errand, or an info dump disguised as a scene."
  - Template fields: Register (social/exploratory/combat/revelation/hybrid); Reskin (reusable pattern note); DM-facing brief of 2–3 sentences where "The default outcome is the most important sentence — it tells you what the scene is about"; `[!secret]` = "your improv fuel — when the scene stalls, crack this open"; opening read-aloud where "First sentence establishes space; second establishes the wrong thing"; NPC opening line that "Must reveal their Active Problem or Consistent Method in subtext. Not exposition"; **If the party pushes back** = "a behavioral rule," not a script; **If the party ignores this** = "must be observable later — another NPC mentions it, evidence appears, or it escalates into a future session's Strong Start."
  - Every island needs: an entity with an `active_problem`; a pressure that resolves itself if unattended; ≥1 PC whose backstory makes it personal; a default outcome the GM can narrate if the party never shows.
  - Failure-mode table: **Info Dump** (info is the reward, not the scene), **Skill Gate** ("the check opens a door, but behind it is a *new* choice"), **No-Stakes Meeting** (add a clock or competing interest), **Railroad** ("If you can't imagine the party not doing this, you've written a railroad" — write the default outcome as a complete scene), **Dead NPC** (no Active Problem = set dressing, wire to a pressure or cut), **Double Register** ("Alternate registers… Rhythm prevents fatigue").
  - Good-vs-bad example: bad Voss = quest-giver, "the party can say 'no thanks' and nothing changes"; good Voss = loading contraband with inspectors 20 minutes out — "help, hinder, exploit, or ignore — and each choice has consequences. The default outcome feeds future sessions."
  - Street-bank page shape (calveno): frontmatter `entry_points` (when to reach for the bank) + `narrative_island` parent; intro states drop conditions and that all "can be played social-first and allowed to escalate, or bypassed entirely with no consequence"; a **d6 Quick-Pull Table** (encounter / district / tone, e.g. "The Wrong Mark · Any calle · Comic → brawl"); per-encounter cards = **Setup** (who, what they're about to commit) → `[!read-aloud]` → **What happens** (save/consequence) → **If pursued/cornered** (stats + outcome ladder) → `[!dm]` (when to pull it + one loaded gun — Fen's unexplained hatch key "is a loaded gun for the Warren investigation"); a Combat Escalations section for a recurring antagonist arc; Connections links.
- skip-from-this-file: Obsidian frontmatter conventions, `[!secret]` callout type (CF narrowed callouts — convert the idea, not the syntax).

## 8. Sandbox multi-pass generation

- source: `.claude/skills/sandbox-narrative/references/SANDBOX-PIPELINE.md` (found); `.claude/skills/sandbox-narrative/references/narrative-devices.md` (found)
- destination: discipline notes for `dungeon-design` / `location-design`
- load-bearing:
  - Four phases, strictly ordered ("Never skip phases or merge them"): **1 Architecture** — overarching conflict in one sentence, 2–4 factions with a single proactive goal each, node map, "3–5 faction timelines: what each faction does on days 1, 3, 7 if players don't intervene"; run the Three Clue Rule pass here, "before detailing rooms. Retrofit clue distribution into the node map now, not after." Constraint: "No NPC names, no room descriptions, no secrets yet. Structure only." **2 Entity Generation** — dossiers not backstories (Roleplay Concept, Quote, behavioral quirks, proactive objectives, PC link). **3 Spatial Logic** — map keys only; "At least two routes between significant locations (one fast/loud, one slow/quiet)"; "If the map has a single chokepoint that all paths must pass through, redesign it." **4 Micro-Detail** — OSE point-first room format; Anti-Slop Pass run per room (Deletion Test, Negation Limit, banned structures, Rule of Threes); "Before writing any DC, damage die, or stat value… load CR tables rather than inventing values."
  - Sequencing rationale: "Architecture constrains Entity Gen — you can't place NPCs without knowing the factions. Entity Gen constrains Spatial Logic — you can't place clues without knowing the secrets. Spatial Logic constrains Micro-Detail." Minimum shortcut if the user jumps ahead: "complete Phase 1 and Phase 3… before writing any micro-detail."
  - Context management: "Write each completed phase to disk before starting the next… Keeping all world data in the active context window causes hallucination and slop re-emergence as the context fills."
  - Pre-flight: check index for overlapping entities, pull current hot state, run the relevance pre-screen ("which PC's thread anchors this sandbox?").
  - Narrative devices (companion reference): core principle — "narrative devices are tools for world-building, not plot control. You place loaded guns. Players decide when they fire." Anti-railroading check: "does this require a specific player choice to pay off? If yes, it's a railroad." Chekhov's Gun ("Seed… Don't aim them"); foreshadow "conditions and threats, not events"; Ticking Clock as "primary anti-passivity tool"; Three Clue format (Conclusion + 3 clues with location/how/what-it-reveals); Escalating Stakes ("Track consequences.

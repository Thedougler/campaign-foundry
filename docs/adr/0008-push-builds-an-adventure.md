# Push builds a Foundry Adventure; the MCP bridge handles live touches

Push compiles the Session's Foundry scenes (walls, doors, lights, tokens), Actors, Journals and Items into a Foundry Adventure, packed offline with the official Foundry CLI into a module for the Campaign's Foundry world, and the DM imports it. Every Wiki page maps to a stable document ID, so a re-import updates documents instead of duplicating them, and each Push carries only what changed in the Wiki since the last one. Hand-tweaks made in Foundry therefore survive until the Wiki page behind them changes. The installed Foundry MCP bridge is used only for live operations an Adventure can't carry, such as player ownership and switching the active Foundry scene, and it never writes content. We chose this split because the bridge cannot create Foundry scenes, walls, lights or token placements, while an Adventure carries every document type natively and needs no running Foundry to build.

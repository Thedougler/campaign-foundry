# Push builds a Foundry Adventure; the MCP bridge handles live touches

Push compiles the Session's Foundry scenes (walls, doors, lights, tokens), Actors, Journals and Items into a Foundry Adventure. The official Foundry CLI packs it offline into a module for the Campaign's Foundry world, and the DM imports it. Each pushed page gets a stable document ID derived from its path. A re-import updates those documents instead of duplicating them. A Push packs only the documents whose Wiki pages changed since the last one, so hand-tweaks made in Foundry survive until the page behind them changes. The installed Foundry MCP bridge handles only live operations an Adventure can't hold, such as player ownership and switching the active Foundry scene. It never writes content. We chose this split because the bridge cannot create Foundry scenes, walls, lights or token placements. An Adventure stores every document type natively, and building it doesn't need a running Foundry.

Push renders Wiki Cues (`==spoken text==`) as HTML `<mark>` elements in journal text, in lists, tables and callouts alike. Code spans are left as written. Statblock attack activities accept the 2024 `Attack Roll:` and `Hit:` labels with or without italics, and distances written as `ft.` or `feet`. The printed attack bonus and damage pass through unchanged.

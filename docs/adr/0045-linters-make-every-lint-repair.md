# Linters make every lint repair
Partly superseded by [0047](0047-agents-lint-their-own-work.md) (the editing agent lints its own files, the `linter` is a convenience, and its dispatcher aligns rules and templates first).

Amends [ADR 0036](0036-skills-prompt-positively-the-linter-repairs.md), whose writer repaired its own findings, and [ADR 0040](0040-templates-are-minimal-by-default.md).

Until now, the agent that wrote a page or skill also repaired its gate findings: root `AGENTS.md` **Gate scope** told every writer to repair each finding before opening its next page, and the `linter` agent took a file only when an agent chose to hand one over. Repair loops filled the context of writers and orchestrators that the DM pays for at the top tier, and each agent repaired in its own way. The DM decided that every lint repair goes to the `linter`, a cheap single-file agent. Writers keep drafting. The linter's first batches showed the cost of that trade. A fallback model on the `linter` recast "reuse, adapt or create" as "reuse or adapt or create" and split sentences to clear a tricolon rule. The DM's instruction was that "the linters shouldn't be assumed to be perfect and should be actively checked for being overly literal".

Decision:

- **The `linter` repairs.** Every lint repair of a finished file, a Wiki page or an agent-facing file alike, goes to the `linter`, one file per dispatch, briefed with that file's path alone. Writers and orchestrators dispatch it as soon as a file's check reports findings and never repair a finding themselves. An agent without the `task` tool returns the dispatch as a request.
- **The dispatcher reviews.** The agent that dispatched a `linter` compares its edits with the file as it stood before the dispatch. A repair that loses meaning or flattens the voice is reverted or sent back to that linter with the sentence and what it lost. So is one that changes a name or Canon, or that cuts text only to satisfy a rule. The dispatcher also carries out the linter's handoffs to other files.
- **The linter keeps meaning and voice.** `.omp/agents/linter.md` recasts each flagged sentence whole, in the page's own voice, and quotes a finding as failed twice rather than flatten the page.
- **The linter runs cheap, at `:auto`.** Its frontmatter `model` is the `@LINTER` role, `openai-codex/gpt-6-luna:auto` in user `~/.omp/agent/config.yml`, with `retry.fallbackChains.LINTER` falling back to `zai/glm-5.3-flash:auto`. During the first batches Luna was unavailable, the fallback ran on xai Grok, and Grok's credits ran out mid-batch with a 403 that killed four linters, so the DM made flash the standing fallback. The DM then saw flash linters running at maximum effort and chose `:auto`, which the harness already limits correctly, so a `linter` dispatch passes no `effort`.

Consequences: root `AGENTS.md` **Gate scope** states the rule once, and every skill step that checks a page sends its findings to a `linter`. `skill://lint` dispatches linters per page and reviews their pairs. A converted page's findings go to a `linter` when a run later touches it (ADR 0044). The `wiki-check` hook's repair hint still tells the editing agent to repair, which needs a code change to point it at the `linter`.

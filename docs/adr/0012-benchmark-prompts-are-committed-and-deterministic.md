# Prose Benchmark prompts are committed and its pipeline is deterministic

Status: superseded by [ADR 0038](0038-blind-council-benchmark.md). It replaces the prompt set and the one-Judge scoring with DM-written prompt versions and a blind council, and the untracked outputs with a committed run log. Since issue #43 (2026-10-06) the run outputs described below had been untracked files, gitignored with a local archive copy at `archive/evals-benchmark/`.

The first Prose Benchmark runs assembled each prompt by hand. The orchestrator glued an entry's `context` and `prompt` into a brief and wrote the Judge's instructions from memory each time. It recorded a `prompt_sha` that a later run couldn't reproduce. Nobody could audit the cache, since a row claimed a prompt identity nobody could check. Two runs of the same entry weren't guaranteed the same bytes, and their scores weren't strictly comparable.

Now each prompt is a committed artifact and each deterministic step is a `bun run cfcli -- bench` subcommand:

- `evals/prose-bench.yaml` is the one source of truth for the prompt set. Its `bench_version` remains the first 12 hex of its sha256.
- `bun run cfcli -- bench briefs` renders each entry's brief byte-exact into `evals/benchmark-samples/<bench_version>/<id>/<id>.brief.md`, committed with the samples. The brief is `context` followed by `prompt` verbatim, with nothing glued between. Older `bench_version` directories are immutable history and are never re-rendered.
- The Judge scores from the committed template `evals/bench/judge-brief.md`. `bun run cfcli -- bench judge-brief` fills it per anonymised sample, hash-named without family or model, and fixes the output path.
- `bun run cfcli -- bench status` computes the hit rule and prints each MISS's exact omp command. A hit is a scored row matching `bench_version`, entry, family, top pin **and** the rendered brief's `prompt_sha`. `bun run cfcli -- bench extract` parses the events stream (final `turn_end` text, code-fence stripping, the `messages[].usage.totalTokens` fallback). `bun run cfcli -- bench record` validates grades and writes the row, and `bun run cfcli -- bench render` rebuilds `benchmark.md`. The skill (`.agents/skills/run-evals`) is left with the judgement calls of choosing the Judge and concurrency, along with dark-family rulings and reporting.

Consequences: editing the yaml moves `bench_version` and clears the cache wholesale. A change to the brief render or the judge template invalidates through `prompt_sha`, and for the template, comparability rests on git history, as it already does for judge identity. Only the commands write the leaderboard, and the view cannot drift from the data. The six `npc-first-look` rows recorded before this decision were pruned from `evals/benchmark.json` on 2026-09-30. Each had an unverifiable `prompt_sha` from an improvised brief (three judged by Opus 5.5, three by a grok fallback). Their samples, events and grades remain in `evals/benchmark-samples/` on disk, and each entry re-runs under the committed briefs.

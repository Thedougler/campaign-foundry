# Prose Benchmark prompts are committed; its pipeline is deterministic

The first Prose Benchmark runs assembled every prompt by hand: the orchestrator glued an entry's `context` and `prompt` into a brief, wrote the Judge's instructions from memory each time, and recorded a `prompt_sha` no later run could reproduce. The cache could not be audited — a row claimed a prompt identity nobody could check — and two runs of the same entry were not guaranteed the same bytes, so their scores were not strictly comparable.

Now every prompt is a committed artifact and every deterministic step is a `cf bench` subcommand:

- `evals/prose-bench.yaml` stays the single source of truth for the prompt set; `bench_version` remains the first 12 hex of its sha256.
- `cf bench briefs` renders each entry's brief byte-exact — `context`, then `prompt` verbatim, no glue — into `evals/benchmark-samples/<bench_version>/<id>/<id>.brief.md`, committed with the samples. Older `bench_version` dirs are immutable history and are never re-rendered.
- The Judge scores from the committed template `evals/bench/judge-brief.md`; `cf bench judge-brief` fills it per anonymized sample (hash-named, no family or model) and fixes the output path.
- `cf bench status` computes the hit rule — a scored row matching `bench_version`, entry, family, top pin **and** the rendered brief's `prompt_sha` — and prints each MISS's exact omp command. `cf bench extract` parses the events stream (final `turn_end` text, code-fence stripping, the `messages[].usage.totalTokens` fallback), `cf bench record` validates grades and writes the row, `cf bench render` rebuilds `benchmark.md`. The skill (`.agents/skills/run-evals`) keeps only what needs judgement: seating the Judge, concurrency, dark-family rulings, reporting.

Consequences: editing the yaml moves `bench_version` and clears the cache wholesale; changing the brief render or the judge template invalidates through `prompt_sha` (for the template, comparability rests on git history, as it already does for judge identity). The leaderboard is written only by the commands, so the view cannot drift from the data. The six `npc-first-look` rows recorded before this decision were pruned from `evals/benchmark.json` on 2026-09-30 — all carried unverifiable `prompt_sha` values from improvised briefs (three judged by Opus 5.5, three by a grok fallback); their samples, events and grades remain in `evals/benchmark-samples/` on disk, and every entry re-runs under the committed briefs.

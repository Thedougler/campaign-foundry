# The Prose Benchmark is a blind council

The Prose Benchmark ranked Matrix families with one anonymous Judge, on prompts an agent excerpted from Wiki pages (ADR 0012). Every family's pin ran as a tool-less `omp -p` process (ADR 0016), and since issue #43 the samples, grades and leaderboard were untracked files. One Judge brings its own model's taste to each score. The agent-written excerpts tested the excerpting as much as the writer, and the untracked outputs didn't record progress. On 2026-10-11 the DM replaced the workflow with a blind council.

Decision:

- **Families with usage.** A run draws from four provider families (Anthropic, OpenAI, Z.ai's GLM and xAI's Grok). It selects each family whose remaining usage can finish the run, by `bun run cfcli -- bench status` and `skill://model-evidence`. For xAI that is the Grok Build limit. The orchestrator judges each family from its remaining fraction and reset time, without a fixed threshold. Each family's seat is one model and one thinking level, set in the frontmatter of its two agent definitions.
  For providers with multiple accounts, `bench status` reports the best account's tightest remaining fraction and that limit's reset, rather than an exhausted sibling account's zero. For xAI, a Grok Build fraction of `0.01` means 1% remains: available is not a guarantee that the quota can finish a Benchmark run.
- **Pending families and amendments.** A family skipped for usage is pending in the run's log entry, with its reason and reset time. A later run of the same prompt version runs only the pending families and amends that entry. The amendment is a new dated entry, and the old entry stays as it was. The amendment copies the earlier samples byte for byte and gives each sample in it a fresh animal name. Then a council of the families now available grades the whole set again. Earlier and new samples look alike to the graders, and each score in the entry comes from one council reading one set. The Leaderboard shows a version's latest entry and keeps the older ones as history.
- **The DM writes the prompts.** A Benchmark prompt is a committed file at `evals/bench/prompts/<id>/v<N>.md`, named by its version `<id>/v<N>`. Only the DM writes, edits or adds one. A changed prompt is a new version file. The DM leaves a version unchanged after its first run. Every selected Runner receives the same prompt file.
- **Isolated Runners.** Each family has a Runner definition, `.omp/agents/bench-runner-<family>.md`, dispatched as a native `task`. The Runner searches the Campaign lore and builds the Wiki page the DM requests in the prompt, such as an Item or a Scene, with its content skill. The page's `> [!narration]` callout, written by `skill://theatre-of-the-mind`, is the craft the council grades first, and the rubric judges the page's mechanics too. The Runner takes Campaign content only from the Notion Backup. For a source work it may read the inspired-by cache (`.cache/inspired-by/`, QMD collection `inspired-by`) and search the web. Beyond the prompt and its craft files, the rest of the Wiki and the repo is off-limits to it, above all Benchmark samples, run logs and the rubric.
- **Anonymous samples.** `bun run cfcli -- bench alias` gives each sample a fresh random animal name and keeps the family mapping outside the repo until grading is done.
- **A council of the same models.** Each selected family also has a grader definition, `.omp/agents/bench-grader-<family>.md`, on the same model as its Runner. Every grader receives every anonymised sample with the prompt and the committed rubric, `evals/bench/rubric.md`. It scores each sample from 1 to 5 per rubric and ranks them all. The council's result is the average across graders. Each model's bias toward its own writing then counts once among several. A sample ranks first only when the whole frontier prefers it.
- **Instructions, not plumbing.** The agents' `tools:` grant `read` and `web_search` with the Notion Backup's read tools and QMD search. The source limits are instructions in each definition, with no hook, wrapper or permission setting to enforce them.
- **A committed log.** Each run writes its log to `evals/bench/runs/<date>-<id>-v<N>/`, with the samples and each grader's grades. The log adds the council result and the revealed mapping, with a report. `evals/bench/leaderboard.md` lists the runs. The repo commits the log and the leaderboard as the versioned record of progress.

This supersedes ADR 0012 and ADR 0016's Benchmark parts: its `omp -p` Benchmark processes and tool-less Benchmark Runners. ADR 0016's skill-eval rules stand. ADR 0013's committed benchmark excerpts are superseded too. Earlier samples, grades and the old leaderboard stay where they are as history, outside the new log.

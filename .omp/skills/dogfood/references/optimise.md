# Optimise

Read this when the DM accepts `dogfood` step 7. The skill already passes its cases, so this phase makes it cheaper: fewer tokens, less time and fewer skill lines for the same verdicts. Cases run per [`evals.md`](evals.md), and round reports go in chat or on the tracking issue.

1. **Baseline.** Run one baseline of the skill's default case (the Runner task without the skill line). When the baseline passes outright, the case cannot show that the skill helps. Harden it with a criterion for a quality the content type demands and an unskilled run misses, or point the prompt at a source an unskilled run mishandles. Then rerun the baseline. Through `skill-writer`, record the verdict, hardening included, in the case's `#` comment. **Done when** the default case fails at least one criterion on its baseline and its comment records the verdict.
2. **Efficiency rounds.** Before each round, snapshot the skill directory with `snap=$(mktemp -d) && cp -R <skill-dir> "$snap/"`. Dispatch `skill-writer` for one patch that cuts tokens, time or skill lines, citing the figure it targets from the last round table. Rerun the cases the patch could affect. Keep the patch when every criterion still passes and tokens or duration fell. Otherwise restore the snapshot with `rm -rf <skill-dir> && cp -R "$snap/<skill-name>" <skill-dir>`. **Done when** the round's table and its keep or restore decision are reported.
3. **Stop** after two rounds that are not kept, or when the DM calls it. **Done when** the last report gives the final token, duration and line counts against the phase's start.
4. **Trigger accuracy.** When the DM names triggering as the problem, run one description pass per `skill://skill-creator` `references/description-evals.md`. **Done when** its results are reported and the kept description validates.

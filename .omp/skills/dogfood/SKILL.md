# Dogfood

Dogfooding improves agent-facing text by using it. Fresh subagents do real work on **units** (one page, one raw file, one finding cluster, one job), report the **friction** they hit, and you turn verified friction into fixes between **iterations**. The work lands for real: the loop leaves the job done as well as the text improved. It is neither an Eval nor a Hillclimb: no `cases.yaml`, and a `prose-grader` only when quality is in doubt. The DM's home Session stays the [Playtest](../../../evals/README.md#weekly-feedback).

You are the **facilitator**: you pick units, dispatch, verify the work, investigate every finding from your view of the whole project and the DM's goal, and brief `skill-writer`, which authors every change to agent-facing text. Investigating before forwarding is the DM's current direction for this skill; it supersedes any injected decision to forward findings undiagnosed.

**Friction** is anything that cost a subagent correctness or time: a confusing, unclear, missing or wrong step; a wrong or missing fact; a tool that misbehaved; a check cycle spent on avoidable work.

## Target

The DM's prompt names the **target** and, optionally, the job. Its **surface** is every agent-facing file the work routes through:

- **One skill** — its `SKILL.md`, the files it points to, and the agents it dispatches.
- **Several skills used together** — each skill's surface, plus the hand-offs between them: shared terms, artifacts one produces and the next consumes, and duplicated or contradicting conventions.
- **A process** — a workflow such as ingesting a raw file end to end or prepping a Session: its entry point and every skill, `.omp/agents/` definition, `AGENTS.md` rule, template and runbook it routes through.

## Steps

1. **Scope.** Name the branch, list the surface, and state the DM's goal for the work in one sentence. Pick live units from the DM's job, or from live state the target governs (for `lint`: pages carrying `bun run cf -- check` findings). Iteration one gives each subagent one small unit, each unit a different case shape (for `lint`: a Creature echo, a played Session record, a Faction, an NPC), and no two units touching the same files. Bare `history://` lists earlier runs on the target; their transcripts are the baseline for cost and duration. **Done when** the surface lists every file the target reaches and every unit is assigned to exactly one subagent.
2. **Dispatch.** One native `task` batch of fresh agents; the per-provider caps in `.omp/AGENTS.md` queue it. Brief each subagent exactly as the target briefs it in production: the skill or process entry point and its real input, with the target's own subagent brief when it has one. Wiki work follows the root Orient order through the skills the subagent loads, so the brief stays the target and its input alone. Steps the target keeps for its orchestrator (logging, generated indexes, the top-level gate) stay with you. A target whose stages the top-level session runs, such as a Transcript's ingest by `ingest` `references/transcript.md`, is a unit you run yourself as that orchestrator, dispatching each stage's subagents with the target's exact task text and acting on the dispatches their returns request. Name each subagent after its unit and stage (`S9Merge`), so its transcript sits at `history://<name>`. Each subagent returns its result and a friction report: per item, what happened and the file and section where it happened. Monitor the batch through `proc://` (running or exited, uptime) and read status and results from `agent://<id>`, leaving the subagents to work unmessaged. **Done when** every subagent in the batch has finished or failed and you hold each report.
3. **Verify the work.** Run the target's gate on every touched file and spot-check quality and facts against their sources. Then read each subagent's `history://<name>` transcript, the primary record of the run: what it actually read and wrote, its tool-call rounds split into procedural (orienting, checks, rework) and content (writing the unit), time to first write, and check cycles. For a staged target, time each stage from its first dispatch to its last return, beside the same stage's time in the last iteration. Self-reported figures are the subagent's own view, cross-checked against the transcript. A failed unit returns to the pool for a later iteration. **Done when** every unit has a verdict and transcript-derived check cycles, round split and duration, and every stage of a staged target has its duration beside the last iteration's.
4. **Investigate.** For each friction item, confirm it in the transcript, reproduce it where the transcript leaves doubt, then trace it to the file that owns the cause; that file may sit outside the surface (another skill, `AGENTS.md`, a template, the CLI). Classify it:
   - **Text gap** (a step, fact or pointer in agent-facing text is unclear, missing or wrong): an issue for `skill-writer`, stated as a process defect with its root-cause file and evidence.
   - **Tool defect** (a CLI, checker or script misbehaves): fix it in code with a test that fails before the fix, or report it to the DM when it lies outside the repo. The text stays free of workarounds.
   - **False finding** (the subagent misread, or the text already covers it): dropped, with the reason.

   Then add what no single subagent could see: friction the transcripts show but the reports omit (rework, wasted rounds, reads that fed nothing), drift from the DM's goal, contradictions between skills or with `AGENTS.md`, a convention duplicated across files, cost or duration that rose without a quality gain. **Done when** every friction item has a verdict and every issue names its root-cause file and evidence (transcript rounds or the reproduction).
5. **Revise.** After every subagent in the iteration has finished, dispatch `skill-writer` once with: the compiled text issues, their evidence, the finished `history://` transcripts of every subagent in the iteration, the code fixes already landed, the surface and root-cause files involved, and whether evals are required. Skip when the iteration surfaced no text issue. **Done when** the writer has yielded and every text issue maps to an edit in its yield.
6. **Validate.** Run `bun run cf -- eval validate <skill-dir>` for each touched skill, and confirm every pointer the writer added or changed reaches an existing file and heading. Return failures to the same writer. **Done when** every touched skill validates and every pointer resolves.
7. **Report.** Tell the DM, for this iteration: units and their verdicts, transcript-derived durations, round splits and cost; each finding with your verdict; code fixes; text changes by file; the plan for the next iteration. When the iteration surfaced no new friction, say so. Ask whether to continue. **Done when** the DM has answered.
8. **Iterate.** On continue, return to step 2 with fresh subagents on fresh units and the revised text. Once small units run clean, scale toward the target's production shape (for `lint`: four to six pages per subagent). The loop ends only on the DM's word; then run the target's shared steps and the page gate over the landed work's pages. **Done when** the DM has confirmed done and the page gate over every landed unit's pages reports `ok: 0 findings`.

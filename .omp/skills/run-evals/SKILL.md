# Run skill evals

This skill is the Eval branch of `evals/README.md`, which defines the terms, safety, grounding, the per-case recipe ([Run a case](../../../evals/README.md#run-a-case)) and the pass rule. An Eval measures and reports, and skill text stays as found. The parent improves the skill from the report through `skill://dogfood`.

## Steps

1. **Select.** Read the skill's case file: `.omp/skills/<skill>/evals/cases.yaml` when the skill is stored there, otherwise `.agents/skills/<skill>/evals/cases.yaml`. The case ids the DM or parent named are the selection; otherwise every case in the file. Each case gets one with-skill run, or one baseline run when the parent's brief requests baselines (README [Design](../../../evals/README.md#design) step 4). Then read `evals/README.md` [Run a case](../../../evals/README.md#run-a-case). Done when every selected id exists in the file and you have each one's `prompt`, `source_pages`, `raw_sources`, `rubrics` and run configuration.
2. **Run.** Follow [Run a case](../../../evals/README.md#run-a-case) for every selected case at once, as its [Concurrency and cleanliness](../../../evals/README.md#concurrency-and-cleanliness) section batches it. Record the run root and dispatch one `task` batch of Runners. Save and split every reply and run its Checks in one Bash call, then dispatch one `task` batch of graders for the cases with rubrics. Write the human-audit pages and run the cleanliness check last. Done when every selected case's `<run>/<case-id>` contains `reply.txt`, `checks.txt`, and `grades.json` when the case has rubrics (or the case's execution or grading error is stated), every case's human-audit page is written, and the cleanliness check has printed its verdict.
3. **Collect.** Read each case's `checks.txt` and `grades.json` and classify the case by the README [pass rule](../../../evals/README.md#pass-rule): pass, quality failure, execution error or grading error. Done when every selected id has one class backed by its Check summary line and its grade entries.
4. **Report.** For each case, give its Checks passed out of total and rubrics passed out of total. List each failed Check and rubric with its reason, each execution or grading error, and the lines of the case's `friction.txt`. Then give the suite score (passing cases over selected cases), the cleanliness result, the human-audit root path, and the model identity, thinking and cost the README [pass rule](../../../evals/README.md#pass-rule) reports where observed. Done when the report accounts for every selected id, unexecuted ids are listed by id rather than counted as passes, the cleanliness check printed `clean` (a `WIKI CHANGED` is reported as an isolation failure), and every skill file is byte-identical to its state at Select.

# Lint

Lint ends on a **clean gate** over its **slice**, the pages it was given or picked. A clean gate is the page gate over those pages at zero findings (root `AGENTS.md` **Zero findings**), played Session records and heard Narration included. Canon sets the facts and the gate sets the form. Each repair keeps what every sentence asserts. Enriching a thin page is a separate `flesh-out` pass, which writes new facts into the page's sections for a Narration recast to use ([prose.md](prose.md) step 1). Lint repairs existing pages in place, adding a page only as the stub step 4 calls for when a page is missing. It splits, deletes and merges none. Resolve every uncertainty from the Wiki by searching QMD (`.omp/AGENTS.md` § Wiki access) and reading the retrieved pages, and decide. The DM gets a result, never a question.

**Every page is its own page.** Like a good book, the Wiki prints each paragraph once. A sentence repeated across pages is **boilerplate**. Replace it with facts found only on that page. Each callout then describes its own subject in its own words. Converted published text is the one exception, by its provenance ([Whole Wiki](#whole-wiki) **Converter output**).

## Steps

1. **Bind scope.** Resolve the active Campaign from `user-config.md` and the request. State the slice. Take the pages the brief hands you, else four to six pages the full gate flags, keeping pages that link one another together and keeping every sharer a `boilerplate` finding names with its page. Brief pages are an Ingest's or Prep's touched pages, or a created or moved page with the pages linking it, or the pages the DM lists. The slice also takes in the stubs and linked pages its findings direct, as [Whole Wiki](#whole-wiki) sets out. A top-level run the DM asks to lint the whole Wiki follows [Whole Wiki](#whole-wiki) instead. Read `docs/wiki-layout.md` for placement. Each page's template sets its sections and fields: `wiki/templates/<type>.md`, or `wiki/templates/<type> - <kind>.md` when the page's frontmatter has a `kind`. **Done when** every command in [Commands](#commands) is bound to the slice's page paths, and you have read the template of each page kind in the slice.
2. **Work list.** Run the bound `bun run cfcli -- check` over the slice paths. Read its full output (the raw artifact, past any truncation) and build a **work list**: every finding, grouped by page. An empty first work list ends the run here. The slice is clean as found: the reply says it passed its page gate untouched, and the run skips the log. **Done when** every finding in the latest output is on the work list.
3. **Repair.** Repair every finding on each work-list page yourself by [Repairs](#repairs), [Names](#names) and [prose.md](prose.md), one page at a time, and keep each recast's before/after pair for step 5. Pages that link one another form a group, since echo compares across links, and so do the sharers of one `boilerplate` sentence, since their recasts must differ from one another. Repair a group's pages one after another. Each recast then starts from its neighbours' finished wording. An edit a repair needs on another page is step 4's. **Done when** every work-list finding has its repair saved.
4. **Other pages.** Make each edit a repair needs on another page. Regenerate the index with `index` ([Commands](#commands)), and set an alias on another page. Add the inbound link for an orphan, and make a **stub** for an `unresolved` link whose page doesn't exist or a rung 3 name ([Names](#names)):
   - **Shape.** Create it from its template with every frontmatter key, every required `##` section and every callout. Leave out each `##` section whose guidance comment opens `Optional.`. Set `revealed` by `CONTEXT.md` **Revealed**, from the PC pages and Session records.
   - **Sources.** Fill each required heading and callout by the root `AGENTS.md` **Sourcing** ladder. Search the Wiki and `archive/` first, citing an archive file in `sources`. Then use the SRD and web sources the kind's design skill fetches. Every fact on a stub traces to one of them.
   - **Statblock.** A Creature's or NPC's statblock is a published one, taken whole by the Reuse or Reskin path of `statblock-design` step 3 and attributed in the page body as that step sets out. The Creature pages that run on an SRD statblock show the form.
   - **Unknowns.** Where the sources leave a required heading empty, write one sentence there saying what the records leave unestablished. The reply counts it as a stubbed section.
   - **Finish.** Run the bound check with `--fix` on the stub to strip the template's `%%` comments and empty `###` headings.

   Read the check of each page this step edited or created, and repair its findings by step 3. **Done when** every such edit is made and each page it edited has a clean check.
5. **Review.** Test each pair against every prose.md pair test, **Print grade** included. A pair that loses meaning or flattens the voice goes back through step 3. **Done when** every pair passes and each recast page's own check still prints `ok: 0 findings`, apart from findings that failed twice (step 7).
6. **Log.** Run the bound log command with `--op lint`, a title that sums up the repairs, and one `--page` per touched page. Include every repaired page, created stubs, indexes and moved pages at their final paths. **Done when** the entry lists every touched page.
7. **Check.** Run the bound page gate once, `bun run cfcli -- check` over the slice, every page this run touched and the Campaign's `log.md`, which step 6 wrote. Each page with a finding goes back to step 3, then step 6 for the newly touched pages. A finding still on its page after its second repair and check has **failed twice**: it leaves the loop unrepaired. **Done when** the page gate reports `ok: 0 findings` (the clean gate), apart from template wording prose.md's `boilerplate/shared-line` rule leaves standing and findings that failed twice, and the log accounts for every repair. The reply states what was repaired in one or two lines. It lists every stub and which of its sections are stubbed. For the DM to settle, it quotes each finding that failed twice with its page, and each suspected false match with its rule and sentence.

## Repairs

Each finding is repaired on its page by these rules, the `narration`, `style` and `boilerplate` findings by [prose.md](prose.md).

- **Mechanics.** A finding outside the `narration`, `style` and `boilerplate` layers (template, placement, links, orphans, statblock, markdown, spelling, grammar, log, hot, index) is repaired against the templates and layout rules, moving existing content intact. `--fix` repairs the four layers [Commands](#commands) names. A finding in any layer whose flagged text is an in-world name or a rules term is settled by [Names](#names). Spelling is British English: a flagged common word takes its British form ("sabre", "rowing boat"). Indexes are generated, so `index` repairs an `index` finding. A `revealed` property that `--fix` added blank takes its value by `CONTEXT.md` **Revealed**, from the PC pages and Session records. An `unresolved` link whose page does not exist, and a name `invented-names` flags that Canon already uses elsewhere (found by a QMD search), each take a stub (step 4).
- **Retired shapes.** A `template` finding that opens `Deprecated` is a section-layout repair, never a prose recast. Migrate the page per root `AGENTS.md` **Migrate retired shapes on touch**. Move each fact into the section whose guidance asks for it and remove the retired heading. Leave out what has no place there. The template and the gate's findings are the only authority on section layout. Another page's layout is never precedent, since untouched pages still have retired layouts.

## Names

A flagged word that is an in-world name or a rules term (`spelling` or `grammar` calls it unknown, or a `style` rule matches the name's own words) keeps its Canon spelling. The gate learns it. Search the Wiki for it (a QMD `lex` query, a glob of its slug), then take the first rung that fits, in order:

1. **Misspelt Canon.** A Canon name spelt another way (the finding's "Did you mean", or a QMD search finds the page) whose referent is that page's subject: write the Canon spelling. Near names can belong to different subjects, so read the flagged text's context against the page first. A different referent goes on down the ladder.
2. **Owned.** A page has the name as its title or in `aliases`. Write that exact form, case included. Or add each form the pages use to that page's `aliases`, one entry per form, whether a plural or other inflected form (`Grubnades`), a short form, a nickname or an epithet.
3. **Unowned.** A name some template fits (a person, place, group, creature, item, god) that no page owns is a missing page, however briefly the text mentions it, and however long it stood on the page before you. The lint run makes its stub as step 4 does, inside its own slice, and a `linter` returns it as a handoff. Ingest gives it a page through its Fill. A run of another skill whose brief keeps that page outside its scope (an Ingest page writer) requests the page in its return, with the page and line that name it, and leaves the finding standing for the run that makes the stub. A name an Ingest pages file lists as a `Coinage:` has been judged outside every template, so it takes rung 4.
4. **Coinage or rare word.** An in-world word or name outside every template (a month, a weekday, a word of an in-world tongue, an oath, an item's command word, the name a character gives a part of themselves) takes one line in `.cspell-words.txt` at the vault root (`wiki/`, or the bound `--vault`). So does a real-world word no dictionary in the gate has, spelt as a reference work prints it (`bodhran`, an Irish frame drum).
5. **Rules term.** A D&D rules or published-setting term: one line in `.cspell/dnd-terms.txt` at the repo root, in its group.

Page names and aliases count in every layer. Both cspell and Harper read them as words, and Harper never flags inside a linked name. The `style` layer swaps each for its kind's noun before Vale reads the page. `invented-names` counts them as Canon. Only cspell and Harper read the word lists. Settle a `style` finding on a name on rungs 1 to 3. Rerun the page check and carry on with the work list. **Done when** the check no longer flags the word and it is known in exactly one place: a page title or alias, `.cspell-words.txt` or `.cspell/dnd-terms.txt`.

## Whole Wiki

A slice is its paths plus each page its findings direct an edit to: the stub for an `unresolved` link or a rung 3 name, and the page an `orphans` finding's hint says to link from. The run makes those edits itself, without asking leave. It re-reads such a page just before editing it, since a sibling slice may have made or changed it, and fills a stub a sibling already made. Each such page joins the run's page gate and log.

The full gate belongs to the top-level agent (root `AGENTS.md` **Gate scope**). It runs when the DM asks to lint the Wiki, or when a top-level operation closes on it. Read its whole output and group the flagged pages into slices. Gather each `boilerplate/shared-line` cluster first: a flagged page with every sharer its findings cite, and the sharers of those sharers. Each cluster goes whole into one slice, whatever its size, since a pair split across concurrent slices leaves each slice a stale work list. Then cut the other flagged pages into slices of four to six, pages that link one another together. Dispatch one fresh `lint` subagent per slice through `task`, briefed with this skill and its slice paths alone. The per-provider caps queue the batch. Each slice ends on its own clean gate, and the Wiki comes clean across as many slices and sessions as its findings need. **Done when** every dispatched slice has returned its clean gate or quoted its findings that failed twice, and the reply states how many flagged pages the full gate still reports and quotes each finding that failed twice.

**Converter output.** Complete pages a deterministic converter wrote (`cfcli convert-items`, `cfcli convert-spells`, `cfcli convert-creatures` and later converters) that no run is otherwise editing carry every mechanical fact their 5e.tools source holds. Each lists its source corpus in `sources`. A line that matches a line of that corpus exactly is exempt from `style`, `grammar` and `boilerplate/shared-line`. A line the converter changed in any way (spelling, spacing, table layout, scaling labels, punctuation) gates normally. The `statblock` layer also exempts derived-number comparisons on proved numeric entry and scalar lines, but schema, missing-field and format checks still apply. For a multiline description, every non-blank content line must match, and its block header does not count. Every other line gates normally, so repetition between agent-written lines is still caught. Their findings are evidence about the converter or the gate's rules, and they take one review in place of per-page repair. Run one bulk check over the batch and cluster its findings by rule, each with its count and two or three quoted examples. A `template`, `markdown` or other structural cluster is a converter defect: request the script fix and a rerun of the batch. A `style` or `grammar` cluster goes to the rule review. Judge whether the rule matches falsely there, applies only optionally or reports too severely. A false match takes a literal-meaning exception in `scripts/vale-patch.ts` or a DM switch-off in `.vale.ini`, and the other two take a proposed scope or level. Take every rule change to the DM as a proposal, since a rule changes only on the DM's confirmation (root `AGENTS.md` **Zero findings**). Edit a converted page only for a wrong or missing fact. A `cfcli convert-creatures` batch skips that bulk review ([ADR 0044](../../../docs/adr/0044-creatures-are-their-statblock.md)). The run that later touches one of its pages repairs that page's findings (root `AGENTS.md` **Gate scope**).

## Commands

These are the Wiki completion commands. Lint runs them, and every skill that files Wiki pages closes through them by **Close** below. Run them from the repo root. Page paths start with `wiki/` (`wiki/shattered-sea/NPCs/Orvalle.md`):

```bash
bun run cfcli -- check "<page path>"
bun run cfcli -- index
bun run cfcli -- check --fix "<page path>" "<page path>"
bun run cfcli -- check "<page path>" "<page path>"
bun run cfcli -- log --op <op> --title "<what changed>" --page "<page path>" --page "<page path>"
```

- **Page check.** The one-path check is each page's own check as you finish it, usually returned by the edit hook (root `AGENTS.md` **Gate scope**). The hook's check leaves out the `boilerplate` layer, which the page gate runs.
- **Index.** `index` regenerates every `index.md` from page `summary` lines. Run it after creating, moving or renaming a page or changing a `summary`. Each `index.md` and `log.md` changes only through these commands.
- **Fix.** `--fix` applies the mechanical fixes of four layers, then re-checks: `template` (leftover `%%` comments, empty `###` and optional `##` headings, missing frontmatter keys), `index` drift, a misplaced page under `placement`, and markdownlint's fixable rules. It fixes `index` drift only in the full gate, and `index` regenerates it otherwise. Every other finding is a hand repair that keeps the page's facts.
- **Page gate.** The many-path check over every page the run touched passes at `ok: 0 findings` (root `AGENTS.md` **Zero findings**). While repairing, `--layer <name>` narrows a check to one layer (repeat it for several, and `bun run cfcli -- check --help` lists the layers). A check with paths leaves out `index`, and it skips `hot`, `log` and `mermaid` when none of its pages is one they check. Every other layer runs, and the full gate runs them all.
- **Log.** `log` appends one entry for the operation to the Campaign's `log.md`. `--op` is the operation: `create`, `ingest`, `prep`, `push`, `audit`, `pull`, `query` or `lint`. `--title` is one line saying what changed. Give one `--page` per touched page, by path or page name, or pipe the list in with `--page -`. `--campaign` is optional. It defaults to the Wiki's only Campaign, and a Wiki of several needs the Campaign's name here (`"Shattered Sea"`, not the folder slug).
- **Another root.** For a Wiki outside this repo that a caller names, add `--root "<root>" --vault "<root>/wiki"` to every command and `--templates "<root>/wiki/templates"` to each check.
- **Umbrella.** The repo-wide `bun run lint` wraps this check as its `prose` scope (`bun run lint prose [--fix] [paths…]`). Lint calls `cfcli check` directly for `--layer`, `--root` and the other flags above.

**Close.** A skill that files pages closes in this order. Run `index` when it created, moved, renamed or deleted a page or changed a `summary`. Run the page gate over every page it touched and repair each finding (root `AGENTS.md` **Gate scope**), then rerun the page gate until it reports `ok: 0 findings`, apart from findings that failed twice (step 7), which the skill's reply quotes for the DM. Then log once, with the skill's `--op`. A skill run on its own logs `create` unless its steps name another op. A skill run inside another operation (Ingest, Prep, Push, Audit, Pull, Query, Lint) returns its touched paths and leaves the log to that operation.

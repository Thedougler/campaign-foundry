# Lint

Lint ends on a **clean gate** over its **slice**, the pages it was given or picked. A clean gate means this run fixed every `bun run cf -- check` finding on those pages. Errors and warnings both count, in played Session records and heard Narration too. A warning is a defect awaiting its fix. The DM sets the facts and the gate sets the form. Each repair keeps what every sentence asserts. Lint repairs existing pages in place, adding a page only as the stub step 3 calls for when a page is missing. It splits, deletes and merges none. Resolve every uncertainty from the Wiki through `qmd`/`query`, reading the retrieved pages, and decide. The DM gets a result, never a question.

**Every page is its own page.** Like a good book, the Wiki prints each paragraph once. A sentence repeated across pages is **boilerplate**. Replace it with facts found only on that page. Each callout then describes its own subject in its own words.

## Steps

1. **Bind scope.** Resolve the active World/Campaign from `user-config.md` and the request. State the slice. Take the pages the brief hands you, else four to six pages the full gate flags, keeping pages that link one another together and keeping every sharer a `boilerplate` finding names with its page. Brief pages are an Ingest's or Prep's touched pages, or a created or moved page with the pages linking it, or the pages the DM lists. The slice also takes in the stubs and linked pages its findings direct, as [Whole Wiki](#whole-wiki) sets out. A top-level run the DM asks to lint the whole Wiki follows [Whole Wiki](#whole-wiki) instead. Read `docs/wiki-layout.md` for placement. Each page's template sets its sections and fields: `wiki/templates/<type>.md`, or `wiki/templates/<type> - <kind>.md` when the page's frontmatter has a `kind`. **Done when** every command below is bound to the World path and the slice's page paths, and you have read the template of each page kind in the slice.
2. **Work list.** Run the bound `bun run cf -- check` over the slice paths. Read its full output (the raw artifact, past any truncation) and build a **work list**: every finding, grouped by page. An empty first work list ends the run here. The slice is clean as found: the reply says it passed its page gate untouched, and the run skips the log. `--fix` repairs four layers' mechanical cases: `template` (leftover `%%` comments, empty `###` and optional `##` headings, missing frontmatter keys), `index` drift, a misplaced page under `placement`, and markdownlint's fixable rules. When the work list has a finding in one of those layers, run the bound check once more with `--fix`, then rebuild the work list from its output. Every other finding is a hand repair. **Done when** every finding in the latest output is on the work list.
3. **Fix mechanics.** Repair every work-list finding outside the `narration`, `style` and `boilerplate` layers (template, placement, links, orphans, statblock, markdown, spelling, grammar, log, hot, index) against the templates and layout rules, moving existing content intact. Work one page at a time: finish its repairs, then read that page's own check ([Commands](#commands)) before you open the next. Repair by [Names](#names) every finding in any layer whose flagged text is an in-world name or a rules term. Spelling is British English: a flagged common word takes its British form ("sabre", "rowing boat"). Indexes are generated: regenerate them with `bun run cf -- index`. An `unresolved` link whose page does not exist, and a name `invented-names` flags that Canon already uses elsewhere (found through `qmd`), each take that page as a **stub**:
   - **Shape.** Create it from its template with every frontmatter key, every required `##` section and every callout. Leave out each `##` section whose guidance comment opens `Optional.`.
   - **Sources.** Fill each required heading and callout by the root `AGENTS.md` **Sourcing** ladder. Search the Wiki and `archive/` first, citing an archive file in `sources`. Then use the SRD and web sources the kind's design skill fetches. Every fact on a stub traces to one of them.
   - **Statblock.** A Creature's statblock is a published one, taken whole by the Reuse or Reskin path of `creature-design` step 3 and attributed in the page body as that step sets out. The Creature pages that run on an SRD statblock show the form.
   - **Unknowns.** Where the sources leave a required heading empty, write one sentence there saying what the records leave unestablished. The reply counts it as a stubbed section.
   - **Finish.** Run the bound check with `--fix` on the stub to strip the template's `%%` comments and empty `###` headings. The stub then passes its page check like any other page.

   **Done when** every finding the bound check still reports, stubs included, sits in `narration`, `style` or `boilerplate` and flags ordinary wording, with names all settled.
4. **Fix prose.** Fix every `narration`, `style` and `boilerplate` finding by [prose.md](prose.md). With up to five work-list pages, or as a subagent, follow it yourself. At the top level with more, dispatch `task` subagents in disjoint batches of eight pages. Each subagent then loads its skills once. Pages that link one another share a batch, since echo compares across links, and so do the sharers of one `boilerplate` sentence, since their recasts must differ from one another. Brief each subagent with its page paths and their work-list findings verbatim. Tell it to load `theatre-of-the-mind` and `skill://lint/prose.md`, follow prose.md and return its touched pages with their before/after pairs. Subagents run page checks only. This run keeps `bun run cf -- check --fix`, the log and the slice's page gate. **Done when** each work-list page's own last check prints `ok: 0 findings`.
5. **Review.** Read every pair, your own included, against prose.md's pair tests: drift (a fact added, dropped, merged, inverted or re-attributed), a Canon name traded for a description, an inverted phrase ("scales of silver"), a line that is less idiomatic aloud than the original, and a shared line that keeps the shared sentence with a clause added where prose.md calls for a recast. Send each failing pair back to the subagent that wrote it by message (`agent://<id>`), citing the sentence and its failure. It keeps its context, redrafts and returns new pairs, and you review those too. **Done when** every pair passes and each redrafted page's own check still prints `ok: 0 findings`.
6. **Log.** Run the bound log command with `--op lint`, a title that sums up the repairs, and one `--page` per touched page. Include every page a subagent returned, created stubs, indexes and moved pages at their final paths. **Done when** the entry lists every touched page.
7. **Check.** Run the bound page gate once, `bun run cf -- check` over the slice and every page this run touched. Any finding returns it to step 3, or to steps 4 and 5, then step 6 for the newly touched pages. **Done when** the page gate reports `ok: 0 findings` (the clean gate), apart from template wording prose.md's `boilerplate/shared-line` rule leaves standing, and the log accounts for every repair. The reply states what was repaired in one or two lines. It lists every stub and which of its sections are stubbed, and each suspected false match with its rule and sentence, for the DM to confirm.

## Names

A flagged word that is an in-world name or a rules term (`spelling` or `grammar` calls it unknown, or a `style` rule matches the name's own words) keeps its Canon spelling. The gate learns it. Search the Wiki for it (`qmd`, a title glob), then take the first rung that fits, in order:

1. **Misspelt Canon.** A Canon name spelt another way (the finding's "Did you mean", or `qmd` finds the page) whose referent is that page's subject: write the Canon spelling. Near names can belong to different subjects, so read the flagged text's context against the page first. A different referent goes on down the ladder.
2. **Owned.** A page has the name as its title or in `aliases`. Write that exact form, case included. Or add each form the pages use to that page's `aliases`, one entry per form, whether a plural or other inflected form (`Grubnades`), a short form, a nickname or an epithet.
3. **Unowned.** A name some template fits (a person, place, group, creature, item, god) that no page owns is a missing page, however briefly the text mentions it, and however long it stood on the page before you. Lint makes its stub as step 3 does, inside its own slice. Ingest gives it a page through its Fill. A run of another skill whose brief keeps that page outside its scope (an Ingest page writer) requests the page in its return, with the page and line that name it, and leaves the finding standing for the run that makes the stub. A name an Ingest pages file lists as a `Coinage:` has been judged outside every template, so it takes rung 4.
4. **Coinage or rare word.** An in-world word or name outside every template (a month, a weekday, a word of an in-world tongue, an oath, an item's command word, the name a character gives a part of themselves) takes one line in `.cspell-words.txt` at the vault root (`wiki/`, or the bound `--vault`). So does a real-world word no dictionary in the gate has, spelt as a reference work prints it (`bodhran`, an Irish frame drum).
5. **Rules term.** A D&D rules or published-setting term: one line in `.cspell/dnd-terms.txt` at the repo root, in its group.

Page names and aliases count in every layer. Both cspell and Harper read them as words, and Harper never flags inside a linked name. The `style` layer swaps each for its kind's noun before Vale reads the page. `invented-names` counts them as Canon. Only cspell and Harper read the word lists. Settle a `style` finding on a name on rungs 1 to 3. Rerun the page check and carry on with the work list. **Done when** the check no longer flags the word and it is known in exactly one place: a page title or alias, `.cspell-words.txt` or `.cspell/dnd-terms.txt`.

## Whole Wiki

A slice is its paths plus each page its findings direct an edit to: the stub for an `unresolved` link or a rung 3 name, and the page an `orphans` finding's hint says to link from. The run makes those edits itself, without asking leave. It re-reads such a page just before editing it, since a sibling slice may have made or changed it, and fills a stub a sibling already made. Each such page joins the run's page gate and log.

The full gate, `bun run cf -- check` with no paths, is the top-level agent's: it runs when the DM asks to lint the Wiki, or when a top-level operation closes on it. Read its whole output and group the flagged pages into slices. Gather each `boilerplate/shared-line` cluster first: a flagged page with every sharer its findings cite, and the sharers of those sharers. Each cluster goes whole into one slice, whatever its size, since a pair split across concurrent slices leaves each slice a stale work list. Then cut the other flagged pages into slices of four to six, pages that link one another together. Dispatch one fresh `lint` subagent per slice through `task`, briefed with this skill and its slice paths alone. The per-provider caps queue the batch. Each slice ends on its own clean gate, and the Wiki comes clean across as many slices and sessions as its findings need. **Done when** every dispatched slice has returned its clean gate, and the reply states how many flagged pages the full gate still reports.

## Commands

Run from the Campaign Foundry project that contains the live Wiki:

```bash
bun run cf -- check --fix "<page path>" "<page path>"
bun run cf -- check "<page path>"
bun run cf -- check "<page path>" "<page path>"
bun run cf -- index
bun run cf -- log --world "<World>" --op lint --title "<what changed>" --page "<Page>"
```

The one-path check is each page's own check, taken from the hook or run by hand as root `AGENTS.md` **Gate scope** sets out, before you open the next page. The many-path check builds the work list in step 2 and runs the page gate in step 7. Repeat `--page "<Page>"` for the complete touched-page list.

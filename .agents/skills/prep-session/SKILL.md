# Prep a Session

Prep produces everything the DM needs to run the upcoming Session from the Wiki alone. The Scene Chart orders pressure and opportunities. The Party's choices and dice determine outcomes.

[The shared Scene procedure](../../../docs/agents/scene-pages.md) owns Scripting the Game order, Scene page contracts, Encounter balance, Narration and conditional handoffs. This skill owns Session composition and the final hot/index/gate/log/Push cycle. Every path below is vault-relative (from `wiki/`). The Session folder is `<campaign-folder>/Sessions/Session <N>/`, and each page in it is titled `Session <N> - <Scene title or kind>` and filed as that title's slug, `session-<N>-<scene-slug>.md`.

## Steps

1. **Orient.** Read `user-config.md`, the Campaign's `campaign-config.md`, its `hot.md` (orientation, not evidence), its Campaign folder's `index.md` and the last ten entries of its `log.md`, in that order. Then read `docs/agents/scene-pages.md` and `docs/wiki-layout.md` whole, and these templates in `wiki/templates/`: `Prep.md`, `Previously On.md`, `hot.md` and `Scene - Hook.md`, `Scene - Development.md`, `Scene - Cliffhanger.md`, `Scene - Climax.md`, `Scene - Resolution.md`. Read each kind's `SKILL.md` (`hook-scene`, `development-scene`, `cliffhanger-scene`, `climax-scene`, `resolution-scene`) now, because charting picks cards from them. **Done when** these files are read and you can identify each template's headings, callouts and properties.

2. **Fix the target and the intent.** The Session to prep is the one the DM names; otherwise it is the Session after the last one with a Recap. Canon runs in this order: what the DM says, then what the Wiki says. The entry state is the end of the last Session the DM counts as played, so read that Session's Recap and final Scene. When the Wiki contains a Recap, a later Previously On or hot claims for a Session the DM calls unplayed, leave those pages unchanged and ground the entry on the earlier Session. Record the conflict for your report.

   When the Session folder already holds a Prep, read it and every Scene page its chart links. This is the existing plan. Rewrite each page at its current path when its row is retained, and give a new row a new path. Every page of a played Session stays as it is. A played Session has a Recap the DM counts.

   Take the settled `plan-session` intent: the DM's fixed points, opening, Threads, Climax, Resolution, Spotlights and decisions left to Prep. An already-settled brief is sufficient. When no intent exists, settle it with the DM through `plan-session`'s checks. **Done when** the Session question and fixed points are stated, World, Campaign, Session N, the entry Session and the existing pages to rewrite are named, and every write has an authorized destination.

3. **Ground the Party.** Search the Wiki (`.omp/AGENTS.md` § Wiki access) and read each page behind a hit in full. A snippet only says where to read. Look for what the entry depends on. Read the entry Session's Recap and final Scene, plus active Threads and open Quests. Read Factions and House Rules in play, and every participating PC's Sheet, Goals and bonds and Plans. Which further pages bear on the intent is your judgement. Follow the links these pages make until the entry has no unsourced dependency. Record the Party's actual Location, in-world date, knowledge, possessions, conditions, resources and live clocks that affect the opening. Distinguish played events from unplayed Prep alternatives. A Creature's statistics are the ones on its Creature page. **Done when** the Hook has a supported entry state, each PC's current level and personal stake are known, and every opening dependency has a source or an explicit design decision consistent with Canon.
4. **Budget and chart.** Read `session_length_hours` from the Campaign overview `<campaign-folder>/<campaign-folder>.md`; when it is blank, use `wiki/dm-settings.md`. Convert it to table minutes. Normally reserve about ninety minutes for Hook, Climax and Resolution together. The middle-Scene ceiling is `max(0, floor((total minutes - 90) / 30))`, not a quota. A four-hour Session permits five middle Scenes. For a shorter Session, keep the three framing Scenes and shorten their allocations to fit. Assign explicit Minutes, leaving room for breaks and rules lookups. Distinguish table time from in-world clock units.

   Order the rows by the shared procedure's **Scripting the Game** section, and choose each row's card from its kind's skill. Use `hook-scene` for Hook and `development-scene` for Development. Use `cliffhanger-scene` for Cliffhanger, `climax-scene` for Climax and `resolution-scene` for Resolution. When the Party spends the middle of the Session moving between Locations, compose those rows with [the travel reference](references/journey.md). The Region page supplies the routes and their costs.

   Format: the Prep template's Scene Chart table with its columns `#`, `Scene` (a link to the row's page), `Kind` (the exact kind), `Minutes` and `Threads` (links). Under the table, one numbered planning note per row, giving its situation, its independent trigger, the selected card, the Spotlight, incoming alternatives, the conditional destination and, where relevant, escalation. A situation comes to the Party through an arrival, a clock, an opposition move or a preceding consequence. The Party chooses how to answer. A Player-dependent detour is a labelled optional branch with a trigger and rejoin state. Make the first physical contest forgiving of sound choices and reserve the opposition's strongest established challenge and the highest stakes for the Climax. **Done when** every row has its kind, purpose, trigger, card, allocation and destination, the order satisfies the shared rules, and the complete allocation fits the Session length.

5. **Distribute Threads, pressure and Clues.** Each part below is a section of the Prep template.

   - `## Threads`: three to five live Threads consistent with the intent, urgent ones first: a Thread that could wait three Sessions is important rather than urgent. Keep faction-driven Threads to two per Session and let at most one major revelation land. One line per Thread, linked, giving where it is planted, tested and moved or conditionally resolved, and the lever it gives the Party. Then fill `### Spotlights` with one line per PC. Map the PC to a linked Scene and state the goal, bond or fear that drives its decision. Include a Thread the Climax touches. Two PCs share a Scene only when each has a distinct opportunity with its own stakes.
   - `## Opposition`: link the opposition and state its Session goal, means and why pursuing that goal brings it into the Party's path. Then its unopposed timeline, one entry per move: in-world time or event trigger, action, observable sign, consequence and what interference changes. Derive the timeline by running `simulate-npcs` with purpose offscreen, over the opposition's leaders and across the Session's in-world span. As a subagent, finish every other heading first, then return the request for that Simulation as `simulate-npcs` sets out, and write the timeline when its report arrives. Keep each move whose sign the Party can perceive. Each sign states what becomes visible and leaves its cause for the Party to infer. The agenda advances without requiring the Party to accept a job or follow a lead. Give each linked speaking cast member a **bench line**: the moment they grab the Scene and how to play them instantly.
   - `## Clues`: fill the template's `| Clue | Found in |` table with about ten distinct true, concrete facts. Each fact is revealable in at least two linked Scenes. State the source or interaction that reveals it at each route. Each conclusion or access essential to progress gets three independent discovery routes across the Session, not three attempts at the same roll. List these in a `###` subsection under Clues. These facts and routes go to each Scene's author to build into its page. Apply `docs/agents/narrative-devices.md` § Planted details and connection, § Clue ladders and § Red herrings.

   **Done when** every Scene advances a live Thread, the selection obeys the Thread and revelation caps, every PC has a driven opportunity, the unopposed timeline is runnable with each sign stating what becomes visible and leaving its cause for the Party to infer, and each Clue and necessary conclusion has concrete discovery routes.

6. **Cast before creating.** Inventory the chart's NPCs, Locations, Creatures, Items and rewards, plus needed Factions, Vehicles, Spells, Lore and Handouts. Follow the shared procedure's **Resolve the cast** step. Search the Wiki for a fitting page first. An unrevealed page (`CONTEXT.md` **Revealed**) that misfits only in its draft details is reflavoured to the role in place of a new page, and a revealed page fits only through additive change. Next search the 2024 SRD through `dnd5e-srd-api`, then published or homebrew material through web search, before novel design. For each missing owner, use its skill: `npc-design`, `location-design`, `creature-design`, `item-design`, `faction-design`, `vehicle-design`, `spell-design` or `lore-design`, and `dungeon-design` when a Site needs area-by-area exploration. When this Prep runs inside a subagent, follow each skill yourself (`AGENTS.md` **Flat dispatch**). A top-level session may delegate independent owner pages concurrently. Author each required Handout from `wiki/templates/Handout.md`, with `theatre-of-the-mind` for its spoken or shown text. Give each owner its purpose, Canon, Party facts, target path and this Prep as the enclosing operation, and keep the final index, gate, log and Push with this Prep. Each page has one writer. **Done when** every required named entity and rules owner exists and is linked from relevant content, NPC combat statistics resolve to Creature owners, and rewards have complete rules and conditional availability rather than name-only promises.

7. **File the Prep.** Fill `wiki/templates/Prep.md` at `<campaign-folder>/Sessions/Session <N>/session-<N>-prep.md`, titled `Session <N> - Prep`. Keep every property, the section order and the `## Links` Base, and remove the `%% %%` guidance comments. Properties: `type: Prep`, a one-line `summary`, `sources` holding repo-relative archived Raw paths (`archive/<file>.md`) used by the Prep or `[]`, and `date` set to the Session's in-world date. `## At a glance` fills its four bullets, Session question (the one question the Climax settles), Party at, Length and Threads in play. File the chart, planning notes, Threads, Spotlights, Opposition with its timeline and bench lines, and Clues as steps 4 and 5 set out. Assign each Scene its path in the same folder: `session-<N>-<scene-slug>.md`, titled `Session <N> - <Scene title>`. Run `bun run cf -- check "<Prep path>"` and repair every finding. **Done when** the filed Prep contains the settled intent and all composition material, every speaking cast member under Opposition has a bench line, every chart row links its assigned Scene destination, and its page check reports `ok: 0 findings`.

8. **Fill every Scene and reconcile.** Work in chart order. For each row, author the Scene through the kind's skill and the shared procedure's **Composed** path, with this Prep as the caller. A top-level session may delegate a Scene to a subagent. Inside a subagent, write it yourself (`AGENTS.md` **Flat dispatch**). Each Scene works from its row and card, Minutes, Party, relevant owner pages, opposition state, Clues and discovery routes, Spotlight, every reachable predecessor outcome and exact destination paths. Receive or record each Scene's touched paths, design decisions, incoming and outgoing states and remaining findings before writing the next.

   Carry alternative knowledge, positions, ownership, conditions, resources and clock states forward as alternatives. A later opening supports success, partial result, failure, delay, refusal or withdrawal whenever those results are reachable. Its Narration and rulings select the corresponding branch. Proposed deaths, captures, rewards and Thread changes stay conditional in Prep and Scenes rather than changing current World pages or `hot.md`.

   After each Scene, update affected rows, routes and receiving entries. If a branch prevents a later premise, replace that premise with its actual consequence and recompute the remaining order and budget; keep the intent's purpose, not a guaranteed victory. If an earlier result can settle the central question, give it a direct Resolution handoff instead of requiring another showdown. **Done when** every charted Scene page is fully authored, its kind's cold-read criteria hold, each possible Encounter has the shared sourced 2024 Party-budget arithmetic from `bun run cf -- encounter-budget` and fought Creature embeds, and every reachable outcome has a coherent receiving entry or Session-ending carry-forward.

9. **Locate Previously On.** The Previously On for Session N lives at `Sessions/Session <N>/session-<N>-previously-on.md` and recounts Session N-1. It is read at the start of Session N. Ingesting Session N-1's Transcript writes it. When it exists, link it from the Prep's opening material and keep its played Narration as it stands. When it is missing, read Session N-1's Recap and have `theatre-of-the-mind` fill `wiki/templates/Previously On.md` at that path, ending on the actual last played moment. An available Transcript in `archive/` supplies grounding. Ingesting unprocessed Raw is `ingest` work. A first Session skips this step. **Done when** the correct prior record is available and linked, or this is the first Session, with no recap of imagined upcoming events.

10. **Supply missing images.** Read the embeds on every cast page and Handout the Session uses, and reuse fitting existing images. Invoke `generate-image` for every missing Battle Map an Encounter needs, NPC or Creature portrait the Session needs, and Handout image, supplying the finished owner page, Canon, target path and this Prep as the completion owner. Independent image jobs may run concurrently. File verified output in `<campaign-folder>/attachments/` as `<Title> - <Kind>.webp` (`Portrait`, `Battle Map`, `Handout`) and embed it as `![[<file>]]`. A Battle Map is 64 px per 5-foot square; check it against its battlefield, and read its Universal VTT file beside it (`<Title> - Battle Map.uvtt` or `.dd2vtt`) for walls, doors and lights. Report missing map data separately from a missing image.

    When image generation, credentials or allowed file operations are unavailable, complete the reachable text and record each missing asset, affected page, attempted operation and exact prerequisite. Keep missing assets out of embeds until real files exist. A spec or an empty placeholder does not count as a generated image. **Done when** each needed image is either verified and embedded or explicitly accounted for as unavailable, and the latter remains an unresolved Prep requirement.

11. **Cold-read the full Session.** Follow each entry and conditional exit across the actual pages and resolving embeds, as a DM with no chat or sourcebooks. Check the chart's shared order and Minutes against the chosen length, each row's trigger and live Thread, the opposition's independent advances, all PC Spotlights, Clue discovery routes and critical-route redundancy. Trace every Climax dependency to an earlier Scene or established Canon, and every Climax result to the matching Resolution payoff, reward, Thread state and closing Narration. Check branch transitions preserve losses and live choices without teleporting the Party or assuming acceptance. Fix local defects and recompute affected rows and entries. **Done when** every row has a runnable page, all conditional routes and payoffs agree, and every composition criterion is satisfied; capability gaps remain named requirements, not fictional successes.

12. **Refresh and file.** Rewrite `<campaign-folder>/hot.md` whole from `wiki/templates/hot.md`, about 500 words and at most 550. Set `date` to the Party's in-world date. Fill `## At a glance` (In-world date, Party at, Active Threads, Last Session, Next), `## Active Threads` (one line per Thread, linked, where it stands and its next move), `## Last Session` (the entry Session's changes, each linked to the page it changed) and `## Next` (links to this Prep and its Hook, and the open questions it is set to run). Future outcomes remain conditional. Then run the **Completion commands** below and record one `prep` operation containing every touched content page, including dependent cast, Handouts, Previously On and hot. **Done when** hot is accurate, the generated index is current, the page gate over every touched page has reported `ok: 0 findings` and the prep log entry exists, or each unavailable operation has its exact blocker recorded.

13. **Push and report.** Follow `push-session` with the World, Campaign, Session, Wiki root and complete touched paths, using the Push commands below and `bun run cf -- push --help` for the current flags. Preview, fix Wiki-side warnings and rerun the gate/log cycle for any additional content edits, then run the actual build without `--dry-run`. A running Foundry or MCP bridge is not required for the offline Adventure build; installation uses only an explicitly supplied modules folder, and the DM performs Adventure import. Live touches remain the Push skill's conditional branch.

    If packing tools, permissions or another real prerequisite are unavailable, attempt the permitted path, retain the observed error and report exactly what remains unavailable. Count only the actual build as a Push. A built module does not prove live import. Report the chart briefly, authored and reused pages, design decisions left to Prep, any Canon conflict from step 2, image status, actual index/gate/log results, Push counts and module path when observed, warnings and remaining DM actions. **Done when** the actual Push or up-to-date result is observed and all Prep requirements hold. Otherwise return the completed artifacts with explicit unresolved requirements and no claim that Prep finished.

## Completion commands

Check each page as you finish it and repair its findings before opening the next page, per `skill://lint` § Commands (**Page check**). After content is ready, close per `skill://lint` § Commands with every touched content page, hot included, logging one `prep` operation with `--title "Session <N> Prep"`. The CLI owns generated index and log files, and an assigned filesystem root takes **Another root** there.

Push through `push-session` (see `bun run cf -- push --help` for the current flags):

```bash
bun run cf -- push --campaign "<Campaign>" --session <N> --dry-run --json
bun run cf -- push --campaign "<Campaign>" --session <N> --json
```

Actual Push writes its own `push` log entry. Report observed results separately for text, images, gate and Push so one successful phase cannot hide an unavailable prerequisite in another.
